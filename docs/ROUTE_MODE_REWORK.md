# Route Mode 修改方案

本方案对应 2026-10-07 的讨论。Route Map 表达围绕学习目标的路线；新方向先提议，用户确认后扩展。任务状态以 [tasks.json](../harness/tasks.json) 为准，本文解释设计、实现顺序和验收方法，不另建进度表。

## 最终行为

学习期间每批最多 5 篇：3 篇路径论文、1 篇探索论文、1 篇持续关注的新进展。探索或新进展缺候选时，先让另一种发现内容补位，再由路径论文补位。路径不足时允许少推；发现内容总数不因此超过 2。目标完成后每日最多 1 篇发现内容，优先探索，再考虑持续关注的新进展。学习期间保持现有手动生成频率；每日一篇限制仅用于目标完成后，以本地日期统一计算。

未回答的路径论文继续轮转，展示次数少的优先。不加冷却时间，不把沉默当负反馈。已回答的论文按现有反馈规则退出日常候选。满足的节点不再承担学习任务；用户勾选“持续关注”后，该节点的新论文才有资格进入新进展位。持续关注与掌握状态分别保存。

探索不是“不匹配已有关键词”。它可以提出已有节点下的新任务、补充缺失的前置，或发现新的分支。检索与排序先用本地规则；需要解释学习价值时，用户主动点击 AI 判断。仅收藏不自动改变 Map，也不自动调用模型。

理工科要求英文。文科项目选择允许的语言。语言限制作用于推荐资格，不删除已有论文，不阻止导入和阅读。元数据语言只是初筛：符合项目规则的论文可以推荐，但必须显示“全文语言未核验”。已核验的全文语言与 PDF 版本绑定，英文标题或摘要不等于英文全文。

## 数据和职责

| 信息 | 保存位置与意义 | 决策方式 |
| --- | --- | --- |
| 项目学科与允许语言 | 项目设置；旧项目首次生成新批次前选择 | 用户明确选择；本地校验 |
| 学习目标与前置关系 | Route Map；目标及其祖先构成当前学习范围 | 用户编辑；AI 只提出草稿 |
| 掌握状态 | 手动标记与有效的读懂反馈 | 本地计算，可撤销 |
| 持续关注 | 节点独立标记 | 用户选择 |
| 论文分类 | 资料库类别和多类别归属 | 保留人工分类与现有关系图 |
| 学习用途 | 同一篇论文可以服务多个概念 | 本地匹配；显示依据与不确定性 |
| 检索来源 | 本次检索的路径、探索或关注主题 | 有界记录，不固定论文终身角色 |
| 推荐类型 | 本次批次中的路径、探索、新进展 | 本地配额和去重 |
| 生长证据 | 明确“有用”或用户选定的种子 | 本地汇总；AI 判断用户主动触发 |
| 扩展提议 | 新任务、前置缺口、新分支或不确定 | AI 草稿，预览后确认 |

关系图回答“论文怎么组织、彼此哪些地方相近”；学习图回答“为了目标先学什么、论文服务哪一步”。类别不自动变成学习节点。两种视图共享论文身份与跳转入口，各自保留用途。Route Mode 关闭后仍可查看和编辑学习图，普通推荐继续使用项目质量与语言规则。

## 按依赖实施

### ROUTE-V2-00：分支、隔离与基线

使用 `codex/route-discovery-rework`，从 `850f9fc` 开始。先确认工作树干净；保留 main 作为回退点。不推送、不合并。每个工作单元完成失败回归、实现、检查、独立审查与桌面构建后本地提交。

桌面后端必须尊重 `PAPERDIGHELPER_DATA`，测试使用临时库、假 HOME 和禁用 AI 的夹具。验证启动、认证、读取隔离论文、父进程退出后的清理，以及默认目录兼容。真实资料库不作为测试夹具。

登记后续阶段的需求和评估。基线 Python 和前端测试、构建结果与命令输出分别保存；已有未通过的发布评估保持原状。

### ROUTE-V2-01：语言策略与迁移

修改 `app/migrations.py`、`app/db.py`、`app/project.py`、项目设置 API 和前端。增加学科、允许语言和策略状态；理工科固定英文，文科显式配置允许语言。旧项目设为待选择，不能由关键词猜学科。

保存 OpenAlex 报告的语言及来源，不用英文标题覆盖它。全文语言核验单独保存 PDF SHA-256、核验方法与状态。PDF 替换后旧核验不再代表当前全文。本轮不自动下载全文核验语言。

旧批次和阅读历史保持可查看；新规则只限制新批次。策略变化使候选资格和相关推荐缓存失效。事务迁移前备份，重复启动不重复迁移。

验收：旧库升级、备份恢复、项目隔离、英文标题中文全文、未知语言、多语言文科、策略改变、PDF 替换，以及迁移中断后的重试。前端必须说明需要选择策略和当前全文核验状态。

### ROUTE-V2-02：统一论文质量入口

建立共享本地资格函数，供普通模式、Route Mode 和自动维护使用。论文至少需要可用摘要，或当前 PDF 版本对应的可用本地正文。只有 PDF 链接或原文页不能当作已有正文。缺摘要的论文保留在库中，但没有正文时不能推荐。

先筛资格，再排序和分配位置。保存具体缺失原因，页面显示数量和原因。正文读取有界，不新增默认模型调用，不把本地正文自动加入外发范围。

验收：有链接无摘要、空摘要、已归档但未抽取正文、有效正文、旧 PDF 正文失效、语言冲突、无候选，以及手动生成与后台维护采用相同判断。验证未反馈论文没有被当成负例。

### ROUTE-V2-03：目标范围、完成与关注

在 `app/pathgraph.py`、`app/service.py` 和 `app/organization.py` 中区分当前目标范围、前沿节点与完成状态。目标及有效前置决定范围；旁支不阻止目标完成。没有前沿不一定完成，也可能有结构问题或候选不足。

持久化持续关注标记，不复用手动掌握字段。Route 保存、读取、组织事件与撤销必须完整保留新增字段。关注节点必须已满足才进入新进展候选。

验收：多目标、旁支、目标完成、缺前置、撤销读懂、手动掌握、关注开关、关闭再开启 Route、重启，以及保存冲突。

### ROUTE-V2-04：三类候选分别召回

刷新时建立有界查询计划：路径围绕当前前沿；探索围绕目标边缘和已确认兴趣；新进展围绕已满足且持续关注的概念。所有查询仍只发送公共检索词，不发送私有种子或画像 ID。

每次刷新最多 3 个查询主题；轮转多个概念，不因三类候选增加总抓取配额。记录本次来源供解释，不改写 `project_papers.relation_kind`。同一篇论文可以由多个主题发现，在批次选择时再决定位置。

验收：查询上限、轮转、跨主题去重、失败重试上限、来源过期和缓存失效。使用固定返回夹具验证，不把夹具结果称为真实召回质量。

### ROUTE-V2-05：统一批次分配

修改 `build_batch`、`_route_pick` 和 `maintenance`，按最终行为执行 3+1+1。保留路径曝光次数轮转。探索要求未展示；持续关注的新进展也不能把已经回答的旧论文重复包装为新内容。

发现内容相互补位，随后路径补位。路径缺失不得扩大发现配额。目标完成后按日控制最多 1 篇；手动点击多次与自动维护不能绕过每日限制。Route 开启时没有候选就说明原因，不静默退回普通推荐。

标签必须显示路径、探索或新进展及依据。无前沿、未选语言、无可读内容、候选不足、目标完成分别呈现。

验收：完整配额、每类缺失、路径不足、全部缺失、重复点击、跨日、已展示未反馈轮转、已反馈退出、已满足但未关注，以及普通模式兼容。

### ROUTE-V2-06：证据与生长提议

修改 `app/pathgrowth.py`、方向判断合同和学习图界面。接受明确有用和用户选定种子作为证据，不局限于历史探索位。纯导入、曝光、收藏记录残留、沉默不是证据。撤销有用后更新有效证据。

判断结果分为：已覆盖、已有节点下的新任务、缺失前置、新分支、看不清。相似度和论文数帮助解释，不作为“能否手动编辑”的硬门槛。AI 看到有界完整 Map；不截成前几个节点来判断覆盖。

展示提议节点、前置、目标影响和依据。用户确认才加入；图更新后旧判断标为过期，不自动付费重判。证据不足时仍允许用户手动编辑。

验收：路径论文支持新任务、近邻可深化、前置缺口、正反馈撤销、种子与导入区分、图改变、重复判断、未知引用和不确定结果。模型不可用时可手动修改，不编造判断。

### ROUTE-V2-07：固定需求表与修改预览

创建和修改统一使用 5 个字段：学习目标 250 字、已知基础 150 字、希望包含 150 字、希望排除 150 字、结构意见 500 字。只要求目标；空基础表示未说明。用户可把老师的意见粘贴到结构意见，不实现通用 MD 文件解析。

创建最多 12 个初始节点。已保存和修改后的 Map 最多 40 节点、120 边、每节点 3 个前置。修改时把完整紧凑 Map、五字段和允许的操作发给模型，要求返回增删改补丁。补丁不是整图替换，不能经创建时的 12 节点归一化裁掉旧图。

服务端只接受白名单字段与操作；引用必须存在，重复和冲突操作拒绝；先合并到副本，再验证，再预览。删除目标必须明确设置新目标，不自动把末端节点当目标。保留显式前置边，难度倒置给警告；环、无效引用和数量超限拒绝。

稳定身份保留手工简介和关注。新增、拆分、合并或语义改变的节点不继承原掌握状态。每节点设置 `progress_since_feedback_id`：只隔离旧熟悉度证据，不删除反馈，也不改变兴趣画像。用户重新确认读懂生成有效新事件，双击仍需幂等。

预览显示结构、目标和进度变化。确认同时检查图版本和有效反馈签名，包含撤销；不能只比较最大反馈 ID。409 时保留草稿并提示重新生成预览，不能更新版本后覆盖旧图。图、需求表和证据截止点在同一原子组织事件中保存并可撤销。

请求前计算完整消息预算；超预算拒绝并说明，不截断 Map。响应 `finish_reason=length` 时拒绝，即使 JSON 能解析。模型草稿不冒充用户记录。

验收：五字段边界、提示注入作为数据、40 节点修改、无修改空补丁、手工字段保护、增删改、拆分合并、目标删除、环、重复引用、显式边、截断响应、读懂重确认、反馈撤销、并发保存、原子失败和撤销恢复。真实 AI 质量单独评估。

### ROUTE-V2-08：视图与完整验收

分类与学习用途分别标示。论文详情显示类别、学习节点和本次推荐用途；两种图可跳转到同一论文，未匹配的论文也有明确入口。Route 关闭不删除 Map。切换项目或视图时取消或忽略过期响应，避免旧项目数据覆盖新页面。 学习匹配与进度共用可用摘要或当前版本有界正文；正文待核验单列，摘要可用时不因语言核验延期隐藏关联。重新核验和阅读器正文保存更新相关缓存。

以临时库完成完整流程：创建项目 → 设置语言 → 建图 → 生成 3+1+1 → 反馈 → 撤销 → 关注 → 完成 → 生成发现 → 修改预览 → 409 → 重新预览 → 确认 → 重启 → 恢复。普通模式单独跑同一质量入口。桌面原生验收与 HTTP/前端模拟分开记录。

## AI 与预算

日常搜索、去重、排序、画像、配额、进度、归档和维护的最低模型开销为 0 token。新增 AI 只在明确点击时经过现有唯一预算网关。未批准的扩展操作不能借用旧授权发请求。

| 操作 | 拟定输入/输出上限 | 触发与频率 | 失败处理 |
| --- | --- | --- | --- |
| 创建路线 | 3200 / 1800 token | 用户点击；保留现有会话及每日次数限制 | 保留需求；手工建图 |
| 修改路线 | 8000 / 4000 token | 用户点击；每项目每日最多 2 次 | 保留草稿；不保存修改 |
| 判断生长 | 8000 / 1000 token | 用户点击；保留每项目每日最多 10 次 | 显示未判断；允许手工编辑 |

这些是待批准提案，不是实际 token 测量。创建旧上限为 1460/1500，方向判断旧上限为 3000/500。全局日/月 token 与金额上限不提高。完整系统提示、需求表、Map、模式约束和协议框架都计入输入；单次最大文本不保证能同时装下。

按仓库登记的峰值缓存未命中价格作算术：单次创建约 $0.00312，修改约 $0.0072，方向判断约 $0.0036。一个月 1 次创建、4 次修改、8 次判断约 125000 token、$0.06072；同场景旧范围 30960 token、$0.014238；增加 94040 token、$0.046482。价格需在真实调用前核对；不能把此提案写成实际账单。

AI 扩展阶段更新预算 JSON、提示词登记和生成文档；新范围保持未批准。离线合同与假响应测试先完成。真实模型质量、tokenizer 一致性和账单校准只有明确批准后才运行。未运行的评估保留 `not_run`。

## 测试和完成标准

每阶段先添加会失败的行为回归，再实现，按影响范围运行测试。全量 Python 测试和前端测试通过后运行桌面构建。构建命令为 `.local/desktop-build-env/bin/python scripts/build_desktop.py`，随后 `cargo tauri build --bundles app`。产物为 `src-tauri/target/release/bundle/macos/PaperDigHelper.app`。

同时运行 `python3 scripts/budget.py --check`、`python3 scripts/harness.py check` 和当前变更记录的 review。保存实际退出码、未运行事项、独立评审发现及修复复查。每工作单元更新 HANDOFF 并本地提交；不能用已有旧产物冒充本次构建。

最终验收必须逐条检查上述规则和真实用户流程，不只看测试数量。`check --release` 中原有的质量、恢复、隐私、资源、预算校准和用户批准门槛不降低。桌面构建成功不等于已证明推荐收益、全文语言准确率或 AI 修改质量。

回退以阶段提交为边界。数据库迁移保持备份和前向兼容；恢复先进入隔离目录验证，不直接覆盖真实库。默认不回退数据库结构，不删除新增用户资料。
