# 预算边界与每日最低开销（额度已批准，运行时拦截仍未实测）

2026-09-11。本页解释可复算预算表。`harness/budget.json` 中 `approved_by_owner=true`，owner 已接受日/月 token 与金额上限；`runtime_enforcement_implemented` 与 `tokenizer_parity_verified` 仍为 false，发布门槛继续阻断。

## 1. 每日最低模型开销：核心是 0 token

推荐与画像主链**不调用生成模型**，每天最低模型 token 为 **0**：

- 论文元数据搜索、候选缓存、去重、版本规范化
- 稀疏排序（BM25/TF-IDF + 线性分类器）、MMR 多样性、曝光控制
- 显式反馈、确定性画像更新、可撤销/可重放
- 归档、SQLite/FTS5 维护、本地周报统计、本地导出
- 手工笔记/高亮、PDF 文本抽取

这些操作**不是零成本**，只是零模型 token。真实成本是：元数据 API 请求数与限额、CPU 时间、峰值内存、磁盘/索引体积、网络外发数据。这些必须在实验中按候选数量实测，当前均为 `not_run`。

## 2. AI 可选层的每日/每月开销（提案）

只有你要求「速览、追问、周报润色、划词翻译」时才产生 token。登记的操作与 envelope：

| 操作 | 触发 | 参考输入 | 参考输出 | 上限输入 | 上限输出 |
|---|---|---:|---:|---:|---:|
| `daily_triage` 五篇速览 | 后台，≤1/天 | 3,000 | 900 | 4,200 | 1,300 |
| `llm_rerank` 混合重排（已批准额度，默认关） | 后台，≤1/天 | 8,000 | 600 | 12,000 | 1,000 |
| `weekly_digest` 周报润色 | 后台，≤1/周 | 2,800 | 700 | 4,200 | 1,100 |
| `paper_qa` 有界追问 | 交互 | 2,600 | 650 | 4,200 | 1,100 |
| `selection_translate` 划词 | 交互 | 700 | 200 | 1,200 | 500 |
| `query_expand` 关键词扩展 | 交互，一次性 | 600 | 200 | 1,000 | 400 |
| `project_guidance` 项目创建引导 | 交互，单会话最多 6 轮 | 800 | 300 | 1,200 | 500 |

**最低 AI 开启成本**（`daily_triage` 1/天 + `weekly_digest` 1/周，DeepSeek peak cache-miss 计价）：

- 每日参考约 **4,500 token**（约 **$0.0023/天**）；上限约 **10,800 token/天**（约 $0.0054）。
- 每月（30 天 + 5 次周任务）参考约 **134,500 token ≈ $0.068**；上限约 **191,500 token ≈ $0.098**。
- DeepSeek 低峰价为峰值一半，实际可能更低；本表按峰值计价，**不假设缓存命中**。

**更重度使用**（速览 + 每天 5 次追问 + 2 次划词）：参考约 **25,450 token/天**、月度参考约 676,000 token ≈ $0.33；请求上限的月度需求约 1,088,500 token，**超过提案的 800,000/月**，会被拒绝，需另行批准更高额度。

**混合大模型重排（ADR 0003）**：`llm_rerank` 每日一次、≤20 篇摘要，默认关闭。owner 已批准覆盖它的更高额度：加上速览与每日 5 次追问后，请求上限峰值日约 **50,300 token**、月度需求约 **1,376,500 token**，均在已批准额度内。它仍默认关闭，直到 `EVAL-01` 对照稀疏基线证明有增益且你启用。

**重试压力场景**（速览2+追问10+划词4+周报2 同日）上限约 81,400 token/天，超过 45,000 日限额，会被拒绝。这只表示需求量，不代表获准执行。

**评估标注实验（一次性，非运行时额度，只记 token）**：裁判用 taomu 中转 / `gpt-6-astra`（[ADR 0004](decisions/0004-evaluation-annotator-separation.md)），与运行时 DeepSeek 分开，避免自己给自己打分。taomu 无公开价格、且每次请求注入约 **4,403 个隐藏输入 token**，因此标注 200 篇（20 篇/次 × 10 次）上限约 **149,030 token，不计算 USD**。详见生成表的「离线评估标注」段与 [EVALUATION](EVALUATION.md)。

**学习图起草（`learning_path_plan` / `learning_path_plan_project`，2026-10-06 变更）**：系统指令加入概念类型（`type`）和可选边界（`boundary`：背景、深度两个枚举值）后，按“全中文最坏情况、每字 1.5 token”的保守估算，输入超出原登记的 1200 约 127 个字符（`tests/test_route_plan.py` 的最坏情况测试）。agent 把两项的输入上限登记为 **1400**（输出上限不变 900；分项 700 + 600 + 100），agent 先把它们登记为未批准；**owner 已于 2026-10-06 在会话中批准**（原话“AI 起草的输入上限我批准了”），现在是 `owner_approved: true`，批准记录和此前的批准（1200/900）都在 `approval_note` 里。所有数字都是启发式估算，未用分词器实测。注意：最坏情况测试沿用了原有的 +150 容差（`cap − framing + 150`），按它，含最长 boundary 的全中文最坏输入估算约 1447 token，仍**高于登记的 1400**；网关只按上限预留额度、发送前并不按输入长度拒绝，所以这是估算与登记值之间的缺口，不是已发生的超支——如要消除这个缺口，需要把上限登记得更高或收紧输入限制，这是另一个需要 owner 决定的变更。
**这两项的次数上限不在 `budget.json` 里**，写在代码中：创建会话首次生成后最多再重新生成 2 次（`routeplan.MAX_REGENERATIONS`，共 1+2 次付费尝试），已有项目每个项目每个本地日最多 3 次（`App.PROJECT_PLANS_PER_DAY`）；网关拒绝而没发出去的不计。`tests/test_route_plan.py` 和 `tests/test_project_manage.py` 固定这两个数；预算检查（`scripts/budget.py`）看不到它们。

**所有数字都是**未实测的计划 envelope（除上述探针外）：参考量来自 arXiv 摘要长度的少量测量与 DeepSeek 官方 token 比例，未经离线 tokenizer 校准前不得称为账单或保证。

5. 真实调用前用离线 tokenizer 校准计数，并核对当前 provider 价格页。

## 3b. 测试模式（不属于正式预算）

开发/试用期间不要被正式日额度卡住，同时又不能污染正式账目：

- 开启：环境变量 `PDH_DEV=1`，或在本机数据目录创建 `DEV_MODE`（都不进 Git）。
- 行为：模型调用改用**独立账本** `usage-dev.jsonl`，套用**独立的宽松额度**（日 500 万 token / $10，月 5000 万 / $50）。
- **不改动**已批准的运行时上限，也不消耗正式账本；页面顶部显示「测试模式」横幅，页脚显示今日用量。
- CLI：`python3 -m app.cli --dev daily --triage`。
- 关闭：删除 `DEV_MODE` 或取消 `PDH_DEV`。正式发布前必须关闭并重新核对额度。

账本、`DEV_MODE` 与 API 密钥都位于**用户数据目录**：源码检出是 `.local/app/`，打包的 macOS 应用是 `~/Library/Application Support/PaperDigHelper/`。它们不会写进只读的应用包，重装应用也不应丢失用量或密钥。
