Implementing agent's own review; not independent (see 2026-10-05-route-runtime-review.md).

- What changed for a project with a map: refresh searches the first term of up to three concepts the reader can read now (relevance order, ten-year window, next page when a page is used up); the daily batch takes its papers from those concepts by weight, introductions first; one remedial introduction per too-hard paper; a smooth deterministic exploration share; no padding from locked concepts; an ordinary batch only when the map has no unshown papers at all, and it says so. Each card carries the concept, layer and kind it was shown under, stored at batch time. A project without a map is unchanged (a test compares behaviour and labels).
- Rules honoured: no model call (the gateway raises in the tests); silence changes no mastery, interest or status (tested after unrated batches); "too hard" is never an interest signal; undo and freeze flow through the same derived progress as the page; the same inputs give the same batches (a second App rebuilt from the same data replays three batches identically).
- Design decision recorded: when the readable concepts run out of unshown papers the app prefers a short batch to borrowing from locked concepts, because the stated goal is to constrain the reader to the path before divergence.
- Migration 008 amended before it ever reached the real database (it adds route_node, route_kind, route_name, route_layer). It was applied to a copy of the real database: 125 exposure rows kept, integrity ok. The real database itself was not touched.
- Weak spots: the weights (1/(1+shown), half for low interest), the one-remedial-per-too-hard rule and the page size 50 are proposals; every number is unvalidated and there is no baseline to show benefit; route_get and _route_pick both assign papers to concepts (about 0.2-0.6 s at 5000 papers); the Today page and profile do not show any of this yet (slice 6b).
