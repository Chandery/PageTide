# Independent review: project scope in the library and knowledge base, first design (2026-10-06)

Reviewer: one separate read-only code-review agent with a fresh context (same model family, not a human). It reviewed the FIRST design of stage 3 (a 当前项目 / 全部项目 switch in the toolbar). The owner then rejected that design (too cramped, and not what was wanted) and asked for project TABS as the outermost level of the left directory; the rewrite kept the same data model (view-level scope, no migration) and the fixes below, but the final tab design and the fixes were NOT re-read by a reviewer.

Findings and disposition
1. MEDIUM, a scope switch in graph mode could overwrite and persist the shared layout (papers newly drawn had no positions, so the radial layout replaced every drawn node and saved them). FIXED: a partial view (a project tab other than all, or a category / paper focus) is laid out in memory only: saved positions are never overridden, positions placed just for the view are tracked (`S.transient`), never captured or saved, and only a node the person drags is saved. A tab click re-renders the sidebar, list and graph without the persist path. Checked in a browser on a copy of the real data: hopping across all tabs and views left the revision (146) and the 19 saved positions unchanged.
2. MEDIUM, 重新排列 nulled every saved position, including the papers not drawn. FIXED: only the drawn nodes are re-arranged, the dialog says so, and with nothing drawn it says there is nothing to re-arrange.
3. MEDIUM, the overview guard (more than 60 papers) was bypassed by picking a category. FIXED: picking a category narrows the focus to that category when the overview is showing.
4. MEDIUM, the focus buttons did nothing while the overview or empty message was shown. FIXED: they redraw whenever the graph view is open.
5. MEDIUM, the new translation key "{0} {1} 篇" rewrote any untranslated "... N 篇" sentence app-wide and dropped the unit. FIXED: the key is removed, the badge title no longer uses it, and two tests pin the property (no entry of the real pack eats the unit, and the guard itself catches such an entry).
6. LOW-MEDIUM, refresh() could select a paper outside the current scope. FIXED (first in-scope paper).
7. LOW-MEDIUM, hidden categories: an empty child could float without its hidden parent, up/down could swap with a hidden sibling, and the delete dialog did not mention other projects' papers. FIXED: descendants of a hidden category are hidden with it, moves swap with the next visible category, and the delete dialog says how many papers of other projects lose the category.
8. LOW, collapsed categories hid focused papers and left neighbours floating; an all-hidden graph was blank. FIXED: a partial focus reveals its own papers; the empty message uses the drawn set.
9. LOW, dead branch in graphItems, stale focus after closing the paper pane. FIXED.
Also found by the author while checking in the browser: the project tabs have role=tab, so setMode() restyled them as view tabs (all tabs lost their selected state). FIXED and tested.

Weak tests named by the reviewer, and what changed: the backend "changes nothing" test is replaced by one that compares sqlite total_changes and the event/project/note row counts across repeated snapshots; added tests for the tab handler (no request, shared state untouched, filter/focus/key reset), the sidebar (panel above the directory, counts follow the tab, hidden-category note), escaping of hostile project names, the deleted-project fallback, transient positions not captured, and that setMode touches only the two view tabs. Still not covered by tests: renderGraph itself (no DOM) and PDHOrganization.reset() reopening the view; both were exercised by hand in the browser.

Confirmed sound by the reviewer: _owners/_project_names (read-only, ordering, missing table), stored data untouched by view choices apart from item 1, reachability of selected/empty/parent categories, relations cache and reset races, graph hop logic, XSS in the new innerHTML paths, zero model tokens.
