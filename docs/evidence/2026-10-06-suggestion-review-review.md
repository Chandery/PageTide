# Independent review: the suggestion review (2026-10-06)

Reviewer: one separate read-only code-review agent with a fresh context (same model family, not a human). It found no high-severity defect and nine others. The author fixed them below; the fixes were checked by tests, mutation checks and a browser run on a copy of the real data but NOT re-read by a reviewer.

1. MEDIUM, a stale preview could corrupt the tree (a merge made the kept category its own parent) or recreate a deleted category, because the fingerprint covered paper text only and the worker never saw the revision. FIXED: the preview stores a hash of the categories and every membership (`structure`); apply and the stale flag compare it, and a changed shape refuses with "run it again". As defence in depth the apply code skips, never guesses: a merge only joins copies that still share a parent and are not ancestor/descendant of each other, never re-parents the kept category, and skips an addition whose target category is gone.
2. MEDIUM, the dialog promised that unticked items "will not be proposed again" but only moves were remembered, and clicking apply silently suppressed unticked moves (a "no" inferred from silence). FIXED: only a move marked "keep as is, do not suggest again" is remembered; an unticked move stays open and comes back; the footer states exactly what is remembered. Tests pin both directions.
3. MEDIUM/LOW, a move could delete categories still held by archived papers and the card did not say categories are removed. FIXED: a category is dropped only when no membership at all remains; the move section says that an emptied category is deleted (undoable). Non-topical categories being judged by wording remains possible; moves stay unticked.
4. LOW/MEDIUM, merge cards were thin and the kept copy depended on the scope. FIXED: the kept copy follows the paper counts of all projects (tabs agree) and each card shows every copy's paper and child counts and says sub-categories move too.
5. LOW, composite notices half-translated in English. FIXED: the notice is whole sentences joined by " · ", each translated whole.
6. LOW, finishing with nothing to write created an empty undo step. FIXED: `reviewed` is created only when there is a mark to write (tested).
7. LOW, the automatic mark in the review request used memberships read in a second transaction. FIXED: it only runs when the structure hash still matches the review's, and signatures computed by the review are reused.
8. LOW, the signature included pinned keywords, so changing tabs re-opened dismissed moves. FIXED: not part of it.
9. LOW, smaller: the move reason named one category (now all); a response without suggestions rendered a false all-clear (now an error); generic category names ("Learning", "Model") matched nearly everything (now ignored); an addition's parent that maps to an existing category lands under it.

Added after the owner's report that an uncategorised paper got an empty review: the dialog never says "nothing to change" while unplaced papers have no proposal (they are listed under "还没有归类的论文"), and a category sharing part of a paper's name (e.g. Embodied AI / Embodied Intelligence) is offered as "possibly related", not ticked, best fits only, same-named categories once.

Weak tests named by the reviewer: the page contract test is still a source grep (kept short, one assertion per fact); the "unplaced are always looked at" test now compares both runs; the unticked-merge test now checks the merge comes back; the dead code was removed; added tests for stale structure, vanished targets, archived members, a no-op finish, pending and weak matches, scope of marks.
Confirmed sound: determinism across hash seeds, 2000 papers x 200 categories in about 2 s, forged ids refused, scope isolation, legacy branch, cyclic/missing parents, JS escaping, closing the dialog marks nothing.
