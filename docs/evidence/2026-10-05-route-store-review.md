# Independent review: per-project learning map storage (Route Mode slice 4), 2026-10-05

Reviewer: one separate read-only code-review agent with a fresh context (same model family as the author, not a human); every finding was reproduced with an offline snippet against a temporary data directory. The author fixed all findings with tests written from them; the fixes were NOT re-read by a reviewer.

Findings and disposition (all FIXED):
1. MEDIUM-HIGH, validate()/add_concept() treated proposed edges and archived or proposed concepts as real paths when removing shortcuts, so an active prerequisite could be dropped and a concept unlocked before its prerequisite was met (a -> c active, a -> b proposed, b -> c: the active a -> c was removed). Fix: only active edges between active concepts count as paths or are removed. Tests for proposed concepts, archived concepts and a proposed edge between active concepts; mutation-checked.
2. MEDIUM, re-saving a plan renumbered concepts (c1..cN) while manual marks and start nodes were kept by id, so "I know MBE" silently moved to an unrelated concept. Fix: marks and starts follow their concept by normalised name for a plan save, by id for a structured save, and are dropped when the concept is gone. Tests incl. a reordered plan and an unrelated plan.
3. MEDIUM, POST /api/route had no body cap and normalisation of a huge plan ran inside the write transaction (a 3.9 MB plan held the lock for 32 s). Fix: 1 MB body cap, a 200-concept cap before normalising.
4. MEDIUM-LOW, a non-string project_id crashed the request with an unhandled sqlite error. Fix: _require_project rejects non-strings.
5. MEDIUM-LOW, unbounded extra fields survived validate() (5 MB evidence strings would be copied into every undo event); inf/nan supports failed later with an unhelpful message. Fix: bounded id-like strings and a short evidence list; non-finite supports become None.
6. MEDIUM-LOW, a proposed concept could absorb a paper's feedback as its best concept. Fix: only active concepts collect evidence.
Low items, FIXED: TypeError instead of ValueError for unhashable ids/targets; empty or all-archived maps accepted (now refused); missing targets now default to the sinks like normalize does; a no-op mark or repeated mode bumped the revision and added an undo step (now nothing is written); a plain GET created knowledge-base tables, a row and a full-database backup (reads are now a plain SELECT); route_get read whole paper rows (only key, title, abstract now); plan and graph together silently preferred the plan (now refused).
Also tightened tests the reviewer called weak: the best-concept test now checks which concept got the evidence; the delete test now covers notes, drafts, the shared default row and missing tables.
Confirmed sound by the reviewer: atomic failures leave revision and route unchanged; the revision check; named and generic undo restore route-save/manual/start correctly and interleave with category edits; project isolation (the shared default row is untouched); latest-feedback semantics, freeze cutoff, seed counting and deterministic ties; delete_project keeps the default rows; origin check shared with other POST routes; bad types give 400.
