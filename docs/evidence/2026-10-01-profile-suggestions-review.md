# 审查：知识库整理建议按画像细分（2026-10-01）

变更记录：[2026-10-01-profile-suggestions](../../changes/2026-10-01-profile-suggestions.json)。类别：critical（worker stdin IPC、数据库加列迁移）。

## 原因

- 旧建议用 OpenAlex topic 与宽 Louvain 社区分组。一个研究方向（世界模型）被拆进机器人、多模态、GAN 等学科大类，与画像无关，也分得太粗。
- 工具栏「刷新」与打开页面、保存冲突时的自动刷新重复；「撤销」不说明撤销什么，而且拖动节点、折叠目录也会占用撤销，点了常常没有可见变化。

## 改动

- 新增 `app/organization_facets.py`：
  - 一级类别 = 当前项目的固定关键词（≥2 篇；大部分论文属于更大关键词的，嵌为子类；Jaccard ≥ 0.8 的合并并注明）。
  - 子类 = 类内多篇标题共有的 1–3 词短语，每类最多 6 个。
  - 未被关键词覆盖的论文同样按共同标题短语分组。
  - 兴趣词只用于打平；不使用 topic。
- 匹配按分句标点切段，不跨句。含中文的关键词只做原文匹配，或经词表精确对应英文。超过 12 个一级类别的关键词写进「未单独成类」。
- 画像词经 worker stdin 传入（ASCII 转义 JSON），worker 只接受 `{"profile": …}`，并且只用于 suggest。
- 应用建议时，子类挂在上级之下。
- 工具栏去掉「刷新」。「撤销」带名称；布局保存不入撤销；撤销删除时恢复该类别的位置与折叠状态。
- 旧库 `org_events` 加可空 `label` 列，加列前先写私有备份。
- `clustering.py` 去掉 broad/topic 模式，只服务图谱。删除对应的 `tests/test_broad_organization.py`。

## 独立审查

第一次审查由单独的 code-reviewer 子代理执行（这是代理，不是 owner）。没有阻断问题，提出 7 项，均已修复并补回归测试：

2. 「LLM 推理」退化为 LLM。
3. 撤销删除丢失类别位置。
4. 加列迁移无备份。
5. 短语成员判断 O(n²)。修复前 2000 篇约 33 秒。
6. 兴趣词没有长度和数量过滤。
7. 超出上限的关键词被悄悄丢弃。

次要项也已修复：未改动的保存标为「编辑类别」；撤销事件 id 必须是整数；stdin 用 ASCII JSON。
