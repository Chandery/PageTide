Change: 2026-10-06-icns-1x-slots
Date: 2026-10-06 (agent sandbox; macOS 26.6.2)

Symptom (owner screenshot): icon is fine on the built-in Retina screen but garbled noise on an
external display. Cause: icon.icns stored 1x 16 and 32 px as PNG under icp4/icp5; macOS decodes
those as noise (iconutil -c iconset on the old file gave random pixels for icon_16x16 and
icon_32x32, center pixel (3,34,31) / (57,147,0) instead of navy (28,34,48)). The @2x slots
(ic11/ic12) were PNG and fine, which is why Retina looked correct.

Fix: docs/design/logo/build_icons.py now writes is32+s8mk (16 px) and il32+l8mk (32 px) classic
RLE entries and no icp4/icp5. Other PNG icons and app/static SVGs regenerated byte-identical.

Verification

  (28,34,48,255), corners transparent; contact sheet inspected, shows the sea lion at 16/32 px.
- python3 -m unittest tests.test_app_icon -v : 5 tests, OK. Same tests against the OLD icns:
  2 failures + 2 errors (so they detect the defect).
- bundle: cmp src-tauri/icons/icon.icns == PaperDigHelper.app/Contents/Resources/icon.icns
- python3 scripts/budget.py --check : PASS

  Not touched by this change; not fixed here.

decode of the new icns inspected; python3 -m unittest tests.test_app_icon : 5 OK; app rebuilt, bundle

Follow-up 2 (same day): after the tuned masters the owner still saw the same picture on the

Change made as the strongest lead: Apple's own iconutil writes the 1x 16/32 px slots as ic04/ic05
("ARGB" + RLE planes A,R,G,B), e.g. VS Code's Code.icns, which renders correctly on the same
display. Decoded VS Code's ic04/ic05 to confirm the layout (consumes the payload exactly, image
is the VS Code logo). build_icons.py now writes ic04/ic05 and no is32/s8mk/il32/l8mk, so the icns
has the same entry set as an iconutil-made file: ic04 ic05 ic11 ic12 ic07 ic13 ic08 ic14 ic09 ic10.
tests/test_app_icon.py updated: ic05 planes == PNG of the same 32 px master, ic04 sanity, no icp4/icp5;
5 tests OK. iconutil -c iconset decodes all slots (16/32 centre (28,34,48,255), corner transparent).
App rebuilt 00:27, bundle icns identical to source.
Result on the owner's display: unknown until they look.
