# Independent review: learning_path_plan and the map editor (Route Mode slice 5), 2026-10-05

Reviewer: one separate read-only code-review agent with a fresh context (same model family as the author, not a human). It reproduced each finding offline with stubbed gateways; no model and no network were used. The author fixed all findings with tests written from them; the fixes were NOT re-read by a reviewer.

Findings and disposition (all FIXED):
1. CRITICAL, the regeneration limit was bypassable. The kept plan and the attempt counter were stored in the session draft, but every later guidance write (a paper search, a turn, a preview) rewrites the draft from a fixed set of keys and wiped them: after a search the "kept" plan was re-generated (a paid call) and the counter reset (a loop of regenerate + search made 9 paid calls). Fix: the plan and counter live in their own setting keyed by session; the session view attaches the plan at read time so a reload still restores it; the setting is removed when the session is confirmed or cancelled. Tests interleave searches, previews and turns between generations; mutation-checked (putting the state back in the draft fails 5 tests).
2. IMPORTANT, concurrent requests bypassed the limit (6 threads on separate App objects gave 7 paid calls). Fix: the attempt is reserved before the call under a process-wide lock, and a second request for a session that is generating is refused. Mutation checks: removing the in-flight check, the limit, or the reserve-before-call each fail tests. Removing only the lock survives because the in-flight check and the reservation each protect on their own; the lock closes a tiny window a test cannot hit deterministically.
3. IMPORTANT, paid attempts that returned no usable plan (an unreadable reply, a timeout of unknown cost) did not count, so paid retries were limited only by the daily ceiling. Fix: an attempt counts whenever the provider was reached; it does not count when the gateway refused or rejected before generating (AI off, no key, not approved, budget, dry run, a rejected request). A session now has 1 + 2 paid attempts in total.
4. IMPORTANT, route_ground could hold the request for minutes offline (24 requests and 72 s sleeping for 12 concepts). Fix: the first network error or rate limit stops the rest (reported as "skipped") and no new concept starts after a 20 s deadline.
5. IMPORTANT, the page and the server disagreed on edit validity: a repeated prerequisite ("A / A") and a punctuation-only name passed the page's check but were refused by the server. Fix: prerequisites are de-duplicated and a name needs a letter or digit, with node tests. (The fan-in counting difference stays: the page is only stricter.)
6. LOW, fixed: a kept plan no longer reports "tokens" as if spent now; regenerating asks for confirmation (it overwrites edits and uses an attempt); server messages have English entries; RecursionError on a deeply nested reply is a bad reply; the English-UI instruction estimate (484 token-equivalents by the heuristic) exceeded the registered 450, so the registry split is now 500 instructions / 550 goal and draft / 150 margin inside the unchanged 1200 cap.
Additional finding of my own while fixing 6: a 600-character goal would exceed the 1200 input cap in the all-Chinese worst case, so the goal is now limited to 250 characters and the draft keywords to five of 30 characters (a pessimistic 1.5 tokens per character is tested against the cap).
Left as is, named: if Organization.action fails after the project row exists (an I/O failure), the project is left without its map; the graph is validated up front so this needs a disk failure.
Confirmed sound by the reviewer: the only model call is gateway.call once per invocation with no retry or silent fallback; dry run and AI-off never reach urlopen; registry, prompt file and code agree and budget/harness checks pass; messages() sends only the goal and the keywords; normalize/validate bound the graph and strip papers/grounding/support_label before storage; no XSS (names, terms and needs pass through esc(); notices use textContent); OpenAlex queries go through clean_query and the key header is only attached for api.openalex.org; create_project(route=) validates before creating anything.
