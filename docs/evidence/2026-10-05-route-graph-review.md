# Independent review: the learning map as a graph, project management, AI draft for existing projects (2026-10-05)

Reviewer: one separate read-only code-review agent with a fresh context (same model family as the author, not a human). It could run tests and read the tree but not edit; it did not see the conversation, so it could not know what the owner actually said. It reported 10 findings plus weak tests. The author fixed all of them below; the fixes were checked by tests, mutation checks and a browser preview but NOT re-read by a reviewer.

Findings and disposition
1. HIGH (AGENTS rule 9), the author widened the owner-approved scope of `learning_path_plan` in the registry note with the author's own reading of the conversation while keeping `owner_approved: true`. FIXED: the original approved wording is restored; the existing-project trigger is a separate operation `learning_path_plan_project` with its own prompt file, identical caps and `owner_approved: false`; the gateway refuses it before sending anything. Verified end to end in the browser (refusal text shown, usage 0 tokens, map unchanged) and by tests (the real gateway with `urlopen` patched, attempt refunded, registry flag asserted false so only the owner can change it). The stale "(500)" in the prompt note now says 560.
2. MEDIUM-HIGH, an empty project id fell back to the default (newest) project, so `DELETE /api/projects/` deleted it (reproduced by the reviewer). FIXED: delete, rename and the paid plan call use `_require_project_id` (non-empty text id, no default fallback); tests cover "", spaces, None, numbers, lists, dicts at service level and the empty path segment over HTTP.
3. MEDIUM, long arrows were routed through a mid-row point and cut across the corners of neighbouring nodes (8% of random 6-12 concept graphs). FIXED: an arrow leaves the source, crosses the gap in an S-curve and runs straight down its own lane through each row it passes; the tests now sample the drawn Bezier curves against every node (the old routing fails them: mutation-checked), including the reviewer's 7-concept repro.
4. MEDIUM, (a) an AI draft silently replaced edits made while the call ran and (b) saving it dropped "already known" marks because AI ids are renumbered. FIXED: editing and discarding are locked while a request runs; the draft reuses the saved id of every concept with the same name (`reuseIds`, tested), the AI box says marks are kept only for same-named concepts.
5. LOW-MEDIUM, a failed backup with a `sqlite3.Error` crashed the request and could leave a partial file that counted as a backup. FIXED: the server answers 500 for `OSError`/`sqlite3.Error`, a partial copy is removed, nothing is deleted (tested with a copy that writes a partial file and raises `OperationalError`).
6. LOW, pruning sorted by file time and could drop the new backup when times were equal or future-dated; the glob was not escaped. FIXED: sorted by the timestamp in the name, the new backup is always kept, `glob.escape`; tested with equal and future-dated times and with look-alike files (`.pre-v7.bak`, `notes.pre-delete-1.bak`) that must survive.
7. LOW, odd ids broke the layout (`constructor`, `__proto__`, ids starting with `~`, ids containing `>`, repeated ids). FIXED: Maps instead of plain objects, dummies tracked by identity, JSON edge keys, first of a repeated id wins, only active arrows between known concepts are drawn; tested.
8. LOW, a re-draw lost scroll position, focus and (on the creation page) zoom, and switching concepts discarded a half-typed edit. FIXED: zoom, scroll and the focused concept are kept (browser-checked), switching concepts while editing is refused with a message, the creation page's "known" checkbox keeps focus. Not fixed: nothing warns before leaving the page with an open edit form (the page-level unsaved guard covers saved-but-not-yet-applied drafts only).
9. LOW, missing English entries for four server messages; `aria-live` on the zoom readout; proposed/archived arrows drawn as real. FIXED (entries added, `aria-live` removed, only active arrows count in the helpers and the drawing).
10. LOW, an exception before the gateway call burned a reserved attempt. FIXED for the local part: the messages are built before an attempt is reserved. Not fixed: deleting a project while its plan call is in flight recreates its counter row (harmless orphan).

Weak tests named by the reviewer, and what changed: the layout invariant check now samples the curves; the backup test asserts which backups survive and the failure injected is `sqlite3.OperationalError`; the HTTP plan test was renamed to what it checks and a real successful HTTP plan was added; empty-id, odd-id and draft-replaces-marked-map cases were added. The static contract tests are still mostly source greps (they pin load order, that the page calls the model in exactly one place, the delete gate); they do not prove behaviour.

Confirmed sound by the reviewer: escaping in every innerHTML path of the new code, same-origin checks on the new POST/DELETE routes, id decoding, backup-before-delete order, pruning scope, plan reservation and refund rules under one lock, only the goal and five keywords reach the model, the plan runs only from the click, no node overlaps in 400 random graphs, the switcher's Enter/Space exception.
