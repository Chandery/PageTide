Unit C of the Baidu Scholar work (after unit B, commit 8f2c73a): candidates while creating a project and the manual seed search.

Owner 2026-10-23 (AskUserQuestion, quoted in ADR 0039; owner_approved stays false): "中文关键词发给百度" - "creation queries and seed searches too" - and scope "一次全接".
What leaves the machine in this unit, only with the Baidu switch on and a key saved: a creation search phrase that contains Chinese characters while 中文 is ticked, and a title typed
into the seed search box that contains Chinese characters; both go to qianfan.baidubce.com with the user's own key, one page each, counted in the shared local cap of 40/day and cached 24 h.
Nothing else. No model call, no migration, no network call in any test.

Existing tests changed: none. (tests/test_candidate_quality.py replaces App.guidance_search with a function that has no `languages` parameter; the route therefore passes
`languages` only when the request body has it, which keeps that contract.)

Decisions beyond the brief: a Baidu hit can be added as a seed (the page needs an identifier for each seed): a hit carries seed_id = its DOI, else `baidu:<id>`; the server
remembers hits the person saw in the seed search (in memory, like the OpenAlex seed cache) and, for a DOI OpenAlex does not know, falls back to the remembered hit; a `baidu:` id never
searched for is reported as not_found and does not stop project creation. A Baidu paper id that is not a plain token gets a stable hash key (`baidu:t-<16 hex>`) so a seed identifier can
carry it. Creation candidates get no OpenAlex DOI enrichment. The Baidu problem is returned as `baidu: {kind}` and shown as one fixed phrase per kind; the server text is never shown.

Not verified: Baidu's response shape, page size and ranking; the creation page and seed box only in Node virtual-page tests, not in a browser.
