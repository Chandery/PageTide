# 自审：阅读助手追问——引用占满面板（2026-10-01）

自审，不是独立评审。owner 反馈：追问时引用会占满整个面板，什么都看不见。

## 原因
- UI 重设计时删掉了引用卡片 `.refcard` 的布局规则（原本两行截断），只剩边框和背景，选中的原文整段铺开。
- 引用区位于标题和对话之间，面板没有给对话区保留最小高度，长引用把对话区挤到 24px。
- 同时发现的问题：
  - 中文输入法按回车选词时会直接发送。
  - 回答未返回时再次发送会清空输入框，问题丢失。
  - 选项行 `.popts` 的样式也丢了。
  - 面板里的论文标题与阅读器标题重复。

## 改动（只改前端，/api/qa 与提示词不变）
- 面板结构：头部（助手 + 论文名一行）→ 对话区（可滚动，最小 140px）→ 输入框组合。
- 输入框组合：
  - 上方是引用卡片：左侧红色竖线，标注“引用 · 第 N 页 · 字数”，正文两行截断，点击展开（最高 30vh，可滚动），✕ 移除。
  - 中间是自动增高的多行输入框：Enter 发送，Shift+Enter 换行，输入法选词时的回车不发送。
  - 底部是全文状态、“更多上下文”开关和发送按钮。
- 发送后引用随消息进入对话，显示在问题上方，同样两行截断、可展开；输入框里的引用随即清除。
- 等待回答时发送按钮禁用，输入框内容保留。
- 清空对话后，重新显示起始问题。
- 删除旧的 `.refchip`、`.pref`、`.sugg`、`.ptitle` 等无用样式。

## 预览实测（1280×820，数据在 `.local/ui-redesign-data`）
- 选中第 1 页约 5.4k 字符后点“追问”：

| | 之前 | 之后 |
|---|---|---|
| 引用区高度 | 1344px | 69px |
| 对话区高度 | 24px | 496px |

- 输入法组合中按回车：没有发送，输入框内容保留。
- 普通回车：发送，按钮禁用；忙碌时点发送，“第二个问题”仍留在输入框里。
- 对话中的引用卡片高 69px，展开后 279px，再点收起。
- 回答返回后按钮恢复，引用框清空。这一步产生了一次真实的 paper_qa 调用。

## 测试
- `tests/test_ui_layout.py` 新增两项：
  - 引用两行截断，展开有上限；对话区有最小高度；引用在对话区之后、输入框之前。
  - 输入法回车判断存在；忙碌时先返回，再清空输入。

## 未测 / 风险
- 引用长度没有上限，整页选中会全文发送给模型；卡片会显示字数，是否加上限需要 owner 决定（涉及提示词和预算）。
- .app（WKWebView）里的外观与输入法行为需要 owner 实机确认。
