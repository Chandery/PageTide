# 审查：界面语言切换真正生效（2026-10-01）

变更记录：[2026-10-01-i18n](../../changes/2026-10-01-i18n.json)。类别：critical（prompt、IPC 路由、页面注入脚本）。

## 诊断

- owner 反馈：设置里把语言调成 English，界面依然是中文。
- `app/static/i18n.js` 和 `app/static/i18n/*.json` 从来没有被任何页面加载；服务端也不读取语言设置，设置只是写进了数据目录的 `settings.json`。
- 旧的 `zh-CN.json` 是一份按英文键组织的包，和页面里内联的中文原文对不上，已删除。

## 改动

- `app/language.py`：读取数据目录 `settings.json` 的 `language`，只有 `en-US` 切到英文；文件缺失、损坏、类型不对或其他值一律中文。
- `app/server.py` 的 `data_dir(root)` 与 `App` 用同一规则定位数据目录（`PAPERDIGHELPER_DATA` 优先），请求处理不再为每个页面新建 `App`。
- `app/server.py`：
  - 每个 HTML 页面在 `<head>` 之后注入 `/i18n/current.js` 与 `/i18n.js`。
  - `/i18n/current.js` 只在英文时下发 `en-US.json` 的内容，并把 `</` 转义，语言包无法读取时回退中文。
  - 周报分析、整理建议的名称与理由、候选不足等服务端文字有英文分支。
- `app/static/i18n.js`：
  - 翻译文字节点和 title / placeholder / aria-label / alt，并包装 alert / confirm / prompt。
  - 查找顺序：精确键 → ` · ` 列表逐段（全部命中才替换）→ `{0}` 模式键（复数按第一个数字，`t()` 先选单复数再填命名位置）。
  - 模式的位置：紧挨量词（篇页个条次字周）或在「第/共」之后只接数字；捕获到的中文只有整段是词条、词条组成的 ` · ` 列表或另一句同样规则的模式句才翻译，否则原样保留；捕获和键自己的中文粘连（「收藏夹」对「收藏 {0}」）时放弃该模式。
  - 不是列表的模式键不能吞掉列表（否则「有用 0 · 未知词」会被半翻译且不报漏）。
  - 不翻译：PDF 文本层、`script/style/pre`、`[data-no-i18n]`，以及知识库的标题、摘要、笔记容器（`.org-markdown`、`.org-detail-title`、`.org-abstract p`、`.org-paper-open strong`）；输入框和可编辑区域只翻译提示属性，不动用户输入。
  - `index.html` 给论文标题、摘要、AI 速览正文（「相关：」「注意：」标签仍翻译）、引用原文、用户问题、AI 回答、划词翻译结果标了 `data-no-i18n`；模型给的追问按钮只在整句是词条时替换（`PDHi18n.exact()`）。
  - 没有词条的中文保持原样，记入 `PDHi18n.misses()` 供预览检查。零 token，不出页面。
- `app/static/i18n/en-US.json`：642 条，以中文原文为键。
- `app/service.py`：
  - 推荐理由（`explain`）、本地引导回复有英文分支。
  - 英文时，`paper_qa` 用英文系统指令，`daily_triage`、`project_guidance` 追加一句「用英文回答」（`ENGLISH_OUTPUT`）；速览里这句放在 JSON 格式说明之后、画像和候选文本之前，不排在不可信文本后面。中文时提示逐字不变（测试断言）。
  - 候选不足、周报活动数等英文说明按 1 和非 1 区分单复数。
- `app/organization_facets.py`：英文时不使用中文词表，名称与理由都是英文。
- `app/static/settings.html`：预算行改成 ` · ` 列表，便于逐段翻译。
- `scripts/i18n_extract.py`：静态列出 7 个界面文件里所有中文字符串（JS 字面量和 HTML 文本/属性，`${…}` 记作 `{0}`）。
- `prompts/*.md`：三个 prompt 文档各加「界面语言」一节，写明追加的句子和估算的 40–60 token（估算，未实测）；`paper-vision-qa.md` 写明英文时沿用 paper-qa 的英文系统指令，看图说明附在其后。

## 预算

- 预算登记不变，没有新的模型调用，仍走同一个网关。
- 只在英文界面多一句指令，估计 40–60 token，落在各操作登记的 instructions 分项内；没有实测。英文回答长度可能不同，仍受登记的输出上限约束。

## 测试

- `tests/test_i18n.py`（Python）：
  - 语言设置的各种异常值都回退中文。
  - 用桩替换网关，确认中文时三个提示与原来逐字相同、英文时带英文要求；本地引导和推荐理由在英文下没有汉字。
  - 整理建议英文下没有汉字。
  - 每条界面中文都有英文词条；词条值没有汉字，占位符是键的子集。
  - `/i18n/current.js` 中文时不带词条，英文时不含 `</`；语言包损坏回退中文。
  - 起本地服务确认 4 个页面都注入了脚本，保存设置后 `/i18n/current.js` 立即切换；周报分析随语言切换。
- `tests/test_i18n.cjs`（node）：中文透传、精确键保留空白、模式与复数、整词捕获再翻译、列表全有或全无、未知文字记漏、`t()` 单复数、对话框、真实语言包自检；审查后新增：词、名字、AI 文本不被半翻译（真实语言包：收藏夹、首页、见第 3 页、上篇、撤销重做、「相关：x · 注意：只看了第 3 页」、「世界模型（已加入）」）、模式句嵌套（限流提示、删除类别说明、证据弹窗日期）、不粘连、`exact()`。
- `tests/test_i18n.py` 审查后新增：速览英文指令在候选之前；候选不足英文单数；周报「1 activity」（服务端测试）；`data_dir(root)` 与 `App(root).data` 一致（有无环境变量）；`index.html` 的 `data-no-i18n` 标记和 `i18n.js` 的 SKIP 容器（静态断言，不是 DOM 测试）。
- 完整测试、harness 和 budget 检查的输出见 [tests](2026-10-01-i18n-tests.txt)，在 owner 终端运行（代理沙箱不允许绑定本地端口）。

## 未测/风险

- 没有发出真实的英文 AI 请求，模型是否稳定用英文回答未测。
- 用户数据保持原样：中文项目名、类别名、缓存的中文 AI 速览、AI 文本、论文正文不翻译；知识库摘要为空时的「暂无摘要」在跳过的容器里，英文下仍是中文。
- 新增界面文字若没有词条会保持中文；覆盖测试只扫描静态字符串，运行时拼出来的片段可能漏掉。
- 用户文字（项目名、类别名、钉住的关键词）若恰好和某个词条相同（如「收藏」「论文库」），或形如某句模式（类别叫「来源：arXiv」「有用 3」），英文下会被翻译。
- DOM 遍历没有自动化 DOM 测试，只有静态标记断言和 Chromium 预览；.app（WKWebView）切换语言后需要 owner 实际看一遍。
