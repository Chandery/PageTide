# Independent review: the map drives refresh and batches (Route Mode slice 6a), 2026-10-05

Reviewer: one separate read-only code-review agent with a fresh context (same model family as the author, not a human); findings were reproduced with offline snippets (a 60-project fuzz of 4 batches each at limits 1-10 found no duplicate, no limit overflow and no route pick outside the frontier). The author fixed every finding with tests written from them; the fixes were NOT re-read by a reviewer.

Findings and disposition (all FIXED; mutation-checked):
1. MEDIUM, the exploration slot was held back even when nothing existed to explore, so batches were 4 papers with 15 route papers unread, and the reason printed a false "no more papers". Fix: an exploration slot with nothing to explore returns to the route.
2. MEDIUM, cards stored only the concept id (ids c1, c2... are reused when a map is replaced), so after replacing or switching off the map an old card was relabelled with another concept's name, against the rule that every recommendation says how it was produced. Fix: migration 008 also stores the concept name and layer at batch time; cards use them.
3. MEDIUM, the route refresh asked for the same first 50 results of a concept every time (cached), so once they were shown but not rated nothing new could arrive, and the message was misleading. Fix: discover_topic takes a page, and the refresh asks for the next page once a concept's current page is all in the project; the shortfall wording now says the papers were shown ("rate the ones you saw, fetch new papers, or mark concepts as known").
4. LOW, undated and year-only papers sorted as newest in the route tie-break (and disagreed with the ordinary ranking). Fix: four stable passes; undated papers last.
5. LOW, remedial reading could starve a batch of one, repeated in every batch for ever because too_hard never decays, and was offered for a prerequisite the reader had marked as known. Fix: it needs room (batch of two or more), is one introduction per too-hard paper (counted from the batches already made), and is skipped for a prerequisite marked known. The pathgraph.remedial docstring was reconciled with the order actually used.
6. LOW, performance (5000 papers: build_batch 0.64 s on the route vs 0.47 s ordinary; home +0.18 s): accepted, not changed.
7. LOW, shortfall wording: fixed together with 1 and 3.
8. Test gaps: the tautological assertion, the limit test that deleted batches (batch index never advanced), the trivial project-isolation test and the single-batch replay test were rewritten; tests added for an unfilled exploration slot, a replaced map, undated papers, limit 1 with remedial, repeated refresh pages and the version-7 database layout (a copy of the real database was migrated 7 -> 8 offline).
Confirmed sound by the reviewer: invariants under fuzz; slot arithmetic (remedial never takes the exploration reservation; frontier concepts without papers are filtered out so their slots are redistributed); silence is not an input (after four unrated batches only `shown` changed; mastery, interest, low_interest and status did not); batch_index is per project and deterministic; migration 008 is idempotent and Store.init backs up before it; the new columns break no consumer; refresh then build in maintenance uses the route; outbound data is only concept term strings.
