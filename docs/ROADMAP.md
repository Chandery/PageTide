# 路线：先证明推荐与画像有用，再扩展阅读与 AI

2026-09-11。**本页替代旧 ABCD 路线，不是把旧任务换名重排。** 活跃任务只在 `harness/tasks.json`；本页只解释顺序与关口，不复制会漂移的完成清单。所有数值目标、技术栈和 AI 开关仍是**提案**，待你确认。

## 1. 旧路线为什么失效

- 领域、种子和相关性标签没确定，却把阅读器、数据库、模型网关排在推荐之前。
- 先承诺 Electron/TypeScript/PDF.js 和完整首版功能，再验证技术方案，没有先比较能直接复用的开源产品。
- 推荐与画像排在后续，而「有用吗、学对了吗」长期没有验收数据。
- 把库测试、坐标数学和任务状态当成产品完成。
- 把领域未知当成继续做配套的理由；未知应补需求/样本，而不是转向造阅读器。

## 2. 按风险推进的阶段（覆盖全部能力，但顺序由风险决定）

你要求四类能力都做（推荐、画像、阅读/整理、AI），本路线全部覆盖，但**先做会证伪主假设的部分**：推荐是否有用、画像是否学对。阅读与 AI 只有在核心通过后才可能变成瓶颈。

|---|---|---|---|---|
| **S0 research** | PLAN-01/02、CLEAN-01、BUDGET-01 | 调研选型、边界、可复算预算提案 | 源码/许可/价格核验；假设与0-token口径可见；你确认方向与实验方案 | 缩小目标或换候选，不开始写完整应用 |

## 3. 零 token 的每日最低开销（核心）

搜索、去重、排序、画像更新、归档、数据库维护**都不调用生成模型**，每天模型 token 最低为 **0**。真实的每日成本是元数据 API 请求、CPU、内存、磁盘和时间，必须单独测量。AI 速览/追问/周报是可选层，其 token 与金额提案见 [BUDGET](BUDGET.md) 与 `harness/budget.json`——**未批准、未实测**。

## 4. 首轮实验协议（先小而真实）

以下是**提议的实验规模与目标，待你确认**，不是已测量结果。

### 输入与拆分

- 以一个研究问题为单位，5–10 个正向种子、3–5 个明确反例；无反例时记为未知，不自动制造负标签。
- 采集一个可回放的时间窗，目标约 100–200 篇领域候选。是否够用取决于该领域产出，不截断后宣称覆盖全部。
- 用 `judge_relevance`（deepseek-flash，对排序不可见）对留出集预标；再按 [EVALUATION](EVALUATION.md) 抽检标签质量（`E-LLM-LABEL-VALIDITY`），一致率达标才能把代理标签用于对照；不足时标探索性结果，且同一模型不得同时做重排与最终裁判。
- 计算最终指标前，对算法实际展示结果的并集补齐盲评标签，隐藏算法来源；没有判断的保持未知。
- 静态排名实验的最终留出标签永久不回流训练；跨源同 DOI/arXiv 版本不能一份做种子一份做测试。
- 另设反馈滚动序列：每批先用已有画像预测、锁定并评分，再释放本批明确反馈供下一批；不能同批更新后重算计为改进。
- 按批次可用时间截断摘要版本、候选/背景语料、IDF 拟合数据；记录模型/词表/语料/画像版本。
- 数据源输出、过滤理由、日期、缺摘要、候选截断必须可追溯；保存响应快照以便本地复跑。

### 对照

1. **固定基线**：领域关键词 + 日期，不用画像更新。
2. **开源候选**：优先试现成系统或现有排序器，不先另造一套算法。
3. **反馈版本**：相同后续候选上比较「冻结画像」与「吸收明确反馈的画像」。

同池比较用于测排序；不同数据源的整链路结果另报覆盖。来源许可允许且你同意外发种子 ID 时，Semantic Scholar 推荐 API 可作外部对照，不当成开源本地引擎或强制依赖。

### 看什么

- **覆盖**：种子 ID 解析成功数、已知相关回收数、摘要可用率、发布/索引延迟。已知集合覆盖不是全球召回率。
- **推荐**：每批最多 5 篇。报告 `有用数/实际展示数`、每天展示数、拒绝推荐/不足五篇次数；同时报告固定 `P@5`，禁止只推荐一篇就冒充 P@5=100%。
- **进入试用申请的最低筛选线**：提议累计至少 10 个回放批次，均值 P@5≥0.6 且不低于固定基线。它只表示没有明显劣化，不代表推荐已有增益。
- **推荐与学习的成功线**：PLAN-02 必须在实验前确认「优于关键词基线」和「更新画像优于冻结画像」的正向增益指标、最小有意义差值和样本量，再据留出结果判 E-RANKING/E-FEEDBACK-VALUE。持平或合成方向性案例不能算通过。
- **无收益时的处理**：冻结自动更新是安全回退，不是 gate 通过。若接受仅人工维护画像的降级产品，必须由你另行确认范围。
- **硬不变量**：无重复曝光漏洞、无已撤销反馈残留、无跨项目串画像、no-op 反馈不变、来源/理由不伪造、人工固定项不被隐式覆盖、没空/暂停不产生债务。
- **开销**：按候选数量记录运行时间、峰值RSS、缓存/索引体积、网络请求数、外发数据与费用。首轮对照不调用生成模型、不下载本地模型权重。

这些目标可在实验前调整，不能看过失败结果再降低标准。

## 5. 不预先锁死技术栈

优先验证顺序与项目证据见 [RESEARCH](RESEARCH.md)，形态取舍见 [BRAINSTORM](BRAINSTORM.md)。一个上游能满足核心就使用或小改它；否则只组合必要组件。实验可用上游 Python/稀疏计算及其本地界面，不为迁就旧 TypeScript 栈重写排序算法。「本地优先」不等于永远禁止 loopback HTTP；是否采用本地页面、桌面包装或现有软件插件，在核心试用前评估安全、维护和总资源后再定。
