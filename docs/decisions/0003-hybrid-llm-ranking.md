# ADR 0003：默认稀疏排序，允许显式启用的大模型混合重排

日期：2026-09-11。状态：方向由 owner 明确请求（"搜索算法不一定只用传统算法，可以接入大模型 API 混合使用，不一定为了绝对的解释性和复现性"）；owner 已批准覆盖 `llm_rerank` 的额度（后台 26k/交互 35k/合计 55k 每日、150 万每月、$0.15/日、$1.50/月）。`llm_rerank` 仍**默认关闭**，直到 `EVAL-01` 对照证明收益。修订 ADR 0002 中"排序必须零 token"的边界。

## 背景

原边界（AGENTS 第 4 条、`R-BUDGET`）要求搜索/排序必须零 token。owner 现在希望排序可以混合大模型，并接受解释性/复现性不是绝对要求。

## 决策

1. **默认核心仍是确定性稀疏路径**（BM25/TF-IDF + 线性分类 + MMR），必须离线可用、零 token、可复现。
2. 允许一个**显式启用、单独计量**的 LLM 重排/打分模式：对每天 ≤20 篇候选的标题+摘要重排或打分。
3. 该模式**不是默认必需**；模型不可用、超预算或用户关闭时，回退到确定性结果并明确标注"未重排"，**不静默切换模型**。
4. 解释性要求放宽：LLM 模式不要求权重级解释，但必须**可追溯**——记录模型/版本、输入候选、时间、模式；不得伪造引用或"论文已证明"类断言。
5. 每条推荐标注来源模式（`sparse` 或 `sparse+llm`），可并排对照。
6. **质量必须对照测量**：`EVAL-01` 比较稀疏基线 vs 混合排序的增益；没有增益则默认关闭。
7. 每次调用经唯一预算网关；新增开销超出已批准额度时，先取得 owner 批准再启用。

## 代价与未决

- 新增每日开销（≤20 篇摘要重排）；owner 已批准更高额度（后台 26k/交互 35k/合计 55k 每日、150 万每月），见 `harness/budget.json`。`llm_rerank` 仍默认关闭。
- 可复现性与纯词法解释不适用于 LLM 模式；用固定模型版本 + 输入快照 + 模式标注来减轻。

## 不改变

源文本视为不可信数据、无静默回退/重试循环、私有种子/画像 ID 不外发（只发公开元数据查询）、无托管后端、无本地模型权重下载、每篇推荐仍须可追溯来源。

## 验证

- `harness/budget.json` 的 `llm_rerank`、`hybrid_llm_rerank` 场景、`pending_approval`。
- `E-RANKING`（稀疏 vs 混合对照）、`E-BUDGET`（准入）、`E-NO-MODEL`（模型全不可用时核心仍可用）。
