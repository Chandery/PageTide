# ADR 0020: authoritative local revision preview and atomic confirmation

2026-10-07. Accepted for the backend contract; stage07 remains in progress. Task ROUTE-V2-07, requirement R-ROUTE-V2-07, evaluation E-ROUTE-V2-07 stays not_run until the shared creation/revision UI and model contract are implemented.

`revision-preview` accepts explicit project ID, fixed five-field brief and allowlisted patch. It validates the complete bounded stored Map, computes structure/goal/progress changes and stores one pending draft per project. Preview does not change the saved Map or its undo event. New n# aliases bind to fresh UUIDs once; confirmation replays those exact identities. Invalid previews retain the earlier draft; a newer valid preview replaces it. Project deletion removes the pending setting. The local service and HTTP boundary reject unknown request fields, duplicate JSON keys, nonfinite values and client-authored cutoff fields.

Confirmation accepts only project ID and draft ID. In the Organization BEGIN IMMEDIATE transaction it reads the latest draft and rechecks a digest containing stored graph/revision/manual/start/watch/brief, effective feedback including undo, freeze, seeds, relevant metadata/body identity and exposure dependencies. MAX(feedback.id) alone is insufficient. A changed context returns409 without replacing the draft or graph. Graph, brief, authoritative progress boundaries, organization event and confirmed draft marker commit together; a late marker failure rolls them all back. Repeated confirmation returns the current route without a second event. Undo restores graph/brief/manual/watch/cutoffs together; an undone confirmation cannot be replayed. An unchanged brief/graph makes no second organization event.

Only familiarity is isolated on semantic changes (normalized name, terms, type); interest and feedback history remain. Existing cutoff cannot move backwards. IDs are global, so the authoritative boundary is max(project feedback maximum, frozen through_feedback_id, prior node cutoff). An explicit reset at/after the frozen boundary allows later understanding/difficulty feedback to count for that node without altering frozen interest. A same-action familiarity click generates one fresh event after reset; repeat clicks are idempotent. New nodes never inherit mastery. Hint/intro/reordered terms do not reset. Watch follows stable identity independently of mastery; human intros remain protected.

Legacy structured saves preserve explicit edges and require active explicit targets. They discard client cutoff authority and recalculate new/changed task boundaries. Legacy plan saves are creation-bounded12, preserve matching saved identities/cutoffs/human intros and refuse to crop a saved Map over12. Initial legacy plan creation without a brief retains prior evidence behavior for compatibility; the new five-field creation path still needs UI integration. The old manual editor now allocates fresh node identities after deletion/addition rather than reusing the highest c# number. Rename retains watch; replacement cannot inherit it.

Feedback insertion/duplicate check run in a locked write transaction. Feedback undo, profile freeze/unfreeze and restore-default all hold the same Store lock and require an idle connection; none may commit a pending revision transaction. Independent connections serialize under SQLite. These contracts cover supported service/HTTP entry points; direct raw-connection mutations are not an application API.

No new model operation, prompt, provider call, network query or private-library upload occurs. The expanded AI budget remains unapproved. Full-message budget, gateway registration, shared creation fields, model revision generation, UI preview/409 handling and phase08 remain unfinished. Backend/offline/package tests do not establish native-window behavior, real model quality, recommendation value, tokenizer/billing or reference-machine resources.
