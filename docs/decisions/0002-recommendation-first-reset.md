# ADR 0002：推荐与画像优先，旧 ABCD 路线退出执行

日期：2026-09-11。状态：方向重置来自用户明确请求；具体上游选型、实验阈值和新实现仍是提案。Supersedes ADR0001（旧文档已按清理要求移出工作树，可从Git历史追溯）中先建阅读器及预锁技术栈/算法的决策，不取消隐私、原件保护和预算授权边界。

## 原因

旧路线先做阅读器、SQLite与模型网关，尚未确认领域/种子便宣布A完成。实际GUI存在文本重影与IPC异步结果不可克隆；更重要的是，推荐是否有用、画像是否正确这两个主要风险一直没有用户数据验证。继续修PDF不能修复这个优先级错误。

## 新决策

1. 以研究问题 → 候选 → 有依据的少量推荐 → 明确反馈 → 可撤销画像 → 下一批推荐为最短闭环。
2. 先研究已有产品/代码/许可，验证直接使用或小改上游；不因为已有TypeScript/Electron代码就重写Python推荐器。
3. 优先对arxiv-sanity-X做受限纯推荐适配探针，lite为轻量基线和失败兜底。未完成Mac安装/运行/质量评估，不宣布选型完成。
4. 同时定义画像和反馈语义。未选、未读、没空、稍后、看不懂与明确不相关分开；背景负类不能写成用户dislike事实。
5. 数据覆盖、排序质量、画像更新收益分别设实验关口，时间留出与冻结基线避免自证。没有领域数据就补输入，不转做配套。
6. 阅读器、文献管理连接、AI摘要/问答/周报为可选后置功能，不再全部强塞首版。
7. 旧任务/需求/验收快照归档。用户后续明确要求删除旧PDF开发，故旧源码、依赖和相关工具已移除，不再冻结保留；真实用户数据和Git历史不动。新实施与付费授权不继承，历史失败也不改写成通过。

## 代价与未决点

X依赖与后台默认值需要隔离，lite依赖旧，PaperFlow的语义路线与反馈入口语义需另评；没有零成本开箱即用的证据。若所有候选失败，必须记录不能直接复用的具体缺口，再批准最小自建层，不退回完整阅读器路线。

需要用户给研究方向和少量正/反例，确认实验及开销目标。外部推荐服务会外发种子ID；模型、托管服务、软件写入和发布都仍需单独授权。
