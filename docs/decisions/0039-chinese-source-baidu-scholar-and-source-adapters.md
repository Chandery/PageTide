# ADR 0039：中文文献来源：百度学术（千帆 API）；来源适配接口与 PDF 获取路线

2026-10-23。owner 要给软件接一个中文的、类似 OpenAlex 的来源，选了百度学术，并要求“做个适配接口，能够快速的帮助用户下载 pdf，并且记录下这个需要 key，openalex 也一样，后续要写文档的”。下面的数据外发与额度取舍都是 owner 在同一次对话里逐项选择的，**批准记录在这里作为引文，代码和变更记录里的 `owner_approved` 仍是 false，不由 agent 自填**。

## 背景

- 现在只有一个发现客户端 `OpenAlex`（`app/sources.py`），键、开关、额度、PDF 路线都是围着它写死的；中文文献几乎只能靠 OpenAlex 里零星的中文期刊。
- 百度学术有官方接口（千帆平台“百度学术检索”），要用户自己的千帆 API Key，免费每天约 50 次，返回题名、原文摘要、DOI、关键词、年份、期刊和百度学术页面链接；没有作者、引用数、PDF 链接和具体日期，也没有日期排序。这些字段名都**来自百度文档页，没有一次真实请求验证过**（`harness/sources.json` 的 `CH-BAIDU-SCHOLAR`；旧的未合并 channels 分支里有同一份调研，它的 ADR 0010–0013 与主线编号冲突，只当作分支文档引用）。
- 数据库迁移 005 的编号已被那个旧分支占用，并已在某些真实库上运行过，所以**本功能不做数据库迁移**：所有新状态放在已有列和 `settings` 表里。

## 决定

1. **来源适配接口**（`app/source_adapters.py`）：`SourceInfo` 常量是每个来源的唯一事实（是否要密钥、密钥去哪拿、密钥带来什么、环境变量、格式、语言和检索文字、本地日上限、服务方额度、外发内容、`harness/sources.json` 里的出处）；适配器协议 `search / verify / pdf_routes`；错误分类 `auth_required / quota_exhausted / network_error / unavailable / bad_response / invalid_input / not_found`，错误信息只由类别、HTTP 状态和清洗后的服务方代码组成，服务方原文和密钥永远不进入信息、界面或日志。`OpenAlex` 增加 `OPENALEX_INFO`（密钥可选）和 `verify()`，其余调用方不动（`App.source` 照旧）；新代码走 `App.adapters`。`docs/SOURCES.md` 是将来用户文档的骨架，一条单元测试在某个已注册来源缺少文档小节或密钥要求不一致时失败。
2. **密钥**（`app/source_keys.py`）：每个来源一个 0600 文件（`openalex.key` 不变，新增 `baidu_scholar.key`），环境变量优先，状态只返回“是否已配置”；不进 `settings.json`、网址、缓存、日志、错误信息和任何接口返回。设置页“数据源”每个来源一行：开关、密钥、一个状态词、测试、清除、获取；测试按钮用输入框里的密钥（不保存）或已保存的密钥发**一次**固定公开词，是单元 A 里唯一会向百度发请求的入口。
3. **百度学术默认关闭**，第一次打开时弹出唯一一次确认。适配器：密钥只作为不可重定向的请求头发给 `https://qianfan.baidubce.com`；响应缓存 24 小时（`data/cache/baidu_scholar/`，文件名只由 URL 决定）；**从不请求也从不保存 `aiAbstract`**（AGENTS 第 7 条：模型文字不是论文摘要），缓存前也会剔除；失败不重试。
4. **本地每日上限 40 次**：计数放在 `settings` 表（`source_usage:baidu_scholar:<日期>`），不放缓存目录——“清除已下载的论文信息”会清空缓存目录；每次请求**之前**用一条 `INSERT … ON CONFLICT DO UPDATE … WHERE 计数 < 上限` 原子预留，没有行被改动就是额度用完，不发请求，两个连接同时预留也不会超；缓存命中不占额度；日界按 UTC+8（未验证）；只保留 7 天的计数键。
5. **开放获取事实合并**（`sources.merge_oa`）：`oa_json` 现在有两个写入者。OpenAlex 的六个字段（`is_oa/oa_status/pdf_urls/landing_page/license/version`）只在新报告里出现时才被替换；`pages`（来源页面，如百度学术页）和 `via`（哪个来源报告了页面）合并；谁都不会抹掉对方。`upsert_papers` 与 `set_paper_oa` 都走它。
6. **来源开关的唯一规则**（`user_settings.SourcePolicy`）：原先四处复制的“arXiv 看 arXiv 开关、其余看期刊开关”收成一处，并加入百度学术：只有百度报告的论文看百度开关，OpenAlex 与百度都报告过的论文任一开着就允许。

## owner 的批准（2026-10-23，对话中逐项选择，原文选项标签）

1. “**中文关键词发给百度**”：项目语言策略含中文时，含汉字的关键词（每个项目每次刷新最多 3 个）用用户自己的密钥发给百度学术；创建项目的检索和种子检索也一样。只发关键词，不发画像、笔记、论文库、私有 ID。
2. “**用 DOI 去 OpenAlex 查 PDF**”：百度结果里的 DOI 交给 OpenAlex（每次刷新一批，阅读器打开这类论文时再查一次）找开放获取 PDF 和语言。
3. “**每天最多 40 次**”：本地日上限 40，百度免费额度是 50 次/天，日界按 UTC+8（未验证）。**待办（owner）**：在千帆控制台确认超额是被拒绝而不是被计费。
4. “**百度页面算“需要登录”的来源**”：只有百度学术页面这一条路的论文算 `page`（需要登录的来源），可以被推荐；百度响应本地缓存 24 小时；百度来源默认关闭，第一次打开确认一次。
范围选“**一次全接**”：每日推送（热点模式，中文项目）、创建项目候选（语言含中文时）、种子检索（中文标题）。学习图（beta）刷新：只有顺手能接才接，否则不接并说明。

## 实施状态

- **单元 A（本版）**：接口、密钥、百度适配器（只被测试按钮调用）、合并规则、来源开关规则、设置页、`tools/source_smoke.py`、`docs/SOURCES.md`。应用不会自动向百度发请求。
- 单元 B（每日推送、DOI 补全、语言、PDF 路线）、单元 C（创建项目与种子检索）按各自的变更记录接入，完成后在此处更新。

## 后果

- 百度结果没有作者，只有年份（`published` 记为该年 1 月 1 日，年份 0 视为未知），顺序是百度的相关度，不是日期；同一关键词每天换一页（单元 B）。
- 百度学术页面往往要登录，所以应用只展示、不抓取；PDF 仍靠 DOI→OpenAlex 的开放获取链接，否则由用户在浏览器里取得 PDF 后拖进阅读器。
- 额度用完只暂停百度，不影响其他来源，也不自动加价。

## 未验证项（保持可见）

百度响应的全部字段名与类型、错误码形状（现在按信息文字分类）、密钥格式（现在允许字母、数字和 `. _ ~ + / = : -`）、千帆密钥页面的地址（`SourceInfo.key_url`）、日界时区、超额是拒绝还是计费、`aiAbstract` 是否默认返回、分页是否从 0 开始、每页条数。`tools/source_smoke.py` 用真实密钥跑一次即可核对，之前所有解析都是容错的：缺字段、列表或标量、未知字段都不会崩。

## 不变

不加后端、遥测或云同步；所有模型调用仍走 Gateway，本功能不调用任何模型，核心路径零模型 token；原件、来源引用不改；不从“没点”推断不喜欢。
