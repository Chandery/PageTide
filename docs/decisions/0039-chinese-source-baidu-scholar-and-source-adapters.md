# ADR 0039：中文文献来源：百度学术（千帆 API）；来源适配接口与 PDF 获取路线

2026-10-23。owner 要给软件接一个中文的、类似 OpenAlex 的来源，选了百度学术，并要求“做个适配接口，能够快速的帮助用户下载 pdf，并且记录下这个需要 key，openalex 也一样，后续要写文档的”。下面的数据外发与额度取舍都是 owner 在同一次对话里逐项选择的，**批准记录在这里作为引文，代码和变更记录里的 `owner_approved` 仍是 false，不由 agent 自填**。

## 背景

- 现在只有一个发现客户端 `OpenAlex`（`app/sources.py`），键、开关、额度、PDF 路线都是围着它写死的；中文文献几乎只能靠 OpenAlex 里零星的中文期刊。
- 百度学术有官方接口（千帆平台“百度学术检索”），要用户自己的千帆 API Key，免费每天约 50 次，返回题名、原文摘要、DOI、关键词、年份、期刊和百度学术页面链接；没有作者、引用数、PDF 链接和具体日期，也没有日期排序。这些字段名都**来自百度文档页，没有一次真实请求验证过**（`harness/sources.json` 的 `CH-BAIDU-SCHOLAR`；旧的未合并 channels 分支里有同一份调研，它的 ADR 0010–0013 与主线编号冲突，只当作分支文档引用）。
- 数据库迁移 005 的编号已被那个旧分支占用，并已在某些真实库上运行过，所以**本功能不做数据库迁移**：所有新状态放在已有列和 `settings` 表里。

## 决定

1. **来源适配接口**（`app/source_adapters.py`）：`SourceInfo` 常量是每个来源的唯一事实（是否要密钥、密钥去哪拿、密钥带来什么、环境变量、格式、语言和检索文字、本地日上限、服务方额度、外发内容、`harness/sources.json` 里的出处）；适配器协议 `search / verify / pdf_routes`；错误分类 `auth_required / quota_exhausted / network_error / unavailable / bad_response / invalid_input / not_found`，错误信息只由类别、HTTP 状态和清洗后的服务方代码组成，服务方原文和密钥永远不进入信息、界面或日志。`OpenAlex` 增加 `OPENALEX_INFO`（密钥可选）和 `verify()`，其余调用方不动（`App.source` 照旧）；新代码走 `App.adapters`。`docs/SOURCES.md` 是将来用户文档的骨架，一条单元测试在某个已注册来源缺少文档小节或密钥要求不一致时失败。
2. **密钥**（`app/source_keys.py`）：每个来源一个 0600 文件（`openalex.key` 不变，新增 `baidu_scholar.key`），环境变量优先，状态只返回“是否已配置”；不进 `settings.json`、网址、缓存、日志、错误信息和任何接口返回。设置页“数据源”每个来源一行：开关、密钥、一个状态词、测试、清除、获取；测试按钮用输入框里的密钥（不保存）或已保存的密钥发**一次**固定公开词，是单元 A 里唯一会向百度发请求的入口。
3. **百度学术默认关闭**，第一次打开时弹出唯一一次确认。适配器：密钥只作为不可重定向的请求头发给 `https://qianfan.baidubce.com`；响应缓存 24 小时（`data/cache/baidu_scholar/`，文件名只由 URL 决定）；**从不请求也从不保存 `aiAbstract`**（AGENTS 第 7 条：模型文字不是论文摘要），缓存前也会剔除；失败不重试。
4. **本地每日上限 40 次**：计数放在 `settings` 表（`source_usage:baidu_scholar:<日期>`），不放缓存目录——“清除已下载的论文信息”会清空缓存目录；每次请求**之前**用一条 `INSERT … ON CONFLICT DO UPDATE … WHERE 计数 < 上限` 原子预留，没有行被改动就是额度用完，不发请求，两个连接同时预留也不会超；缓存命中不占额度；日界按 UTC+8（未验证）；只保留 7 天的计数键。
5. **开放获取事实合并**（`sources.merge_oa`）：`oa_json` 现在有两个写入者。OpenAlex 的六个字段（`is_oa/oa_status/pdf_urls/landing_page/license/version`）只在新报告里出现时才被替换；`pages`（来源页面，如百度学术页）和 `via`（哪个来源报告了页面）合并；谁都不会抹掉对方。`upsert_papers` 与 `set_paper_oa` 都走它。
6. **来源开关的唯一规则**（`user_settings.SourcePolicy`）：原先四处复制的“arXiv 看 arXiv 开关、其余看期刊开关”收成一处，并加入百度学术：只有百度报告的论文看百度开关，OpenAlex 与百度都报告过的论文任一开着就允许。

## owner 的批准（2026-10-23，对话中逐项选择，原文选项标签）

1. “**中文关键词发给百度**”：项目语言策略含中文时，含汉字的关键词（每个项目每次刷新最多 3 个）用用户自己的密钥发给百度学术；创建项目的检索和种子检索也一样。只发关键词，不发画像、笔记、论文库、私有 ID。
2. “**用 DOI 去 OpenAlex 查 PDF**”：百度结果里的 DOI 交给 OpenAlex（每次刷新一批，阅读器打开这类论文时再查一次）找开放获取 PDF 和语言。
3. “**每天最多 40 次**”：本地日上限 40，百度免费额度是 50 次/天，日界按 UTC+8（未验证）。**待办（owner）**：在千帆控制台确认超额是被拒绝而不是被计费。
4. “**百度页面算“需要登录”的来源**”：只有百度学术页面这一条路的论文算 `page`（需要登录的来源），可以被推荐；百度响应本地缓存 24 小时；百度来源默认关闭，第一次打开确认一次。
范围选“**一次全接**”：每日推送（热点模式，中文项目）、创建项目候选（语言含中文时）、种子检索（中文标题）。学习图（beta）刷新：只有顺手能接才接，否则不接并说明。

## 实施状态

- **单元 A**（已提交 57f0d70）：接口、密钥、百度适配器、合并规则、来源开关规则、设置页、`tools/source_smoke.py`、`docs/SOURCES.md`。
- **单元 B**（本次）：每日推送、DOI 补全、语言、PDF 路线。
  - 每日推送（热点模式，`App.refresh_candidates`）：百度开关打开、已配置密钥、项目的论文语言含中文、且有含汉字的关键词时，每个项目每次刷新最多 3 个这样的关键词发给百度（只发关键词文字）。百度没有日期排序，所以每个关键词每天问一页：第一次第 1 页，之后每天下一页，满 5 页回到第 1 页，某页返回空则下一天从第 1 页开始（游标 `baidu_cursor_<项目>` 存在 `settings` 表）。同一天再次刷新用 24 小时缓存，不占额度。百度的错误（无效密钥、额度用完、网络/服务问题）记入返回的 `errors`（带 `source: baidu_scholar`），鉴权/额度/网络类错误结束本次的百度部分，OpenAlex 结果照常保留。
  - DOI 补全：百度新结果里的 DOI 合成一批（最多 50 个）交给 OpenAlex（`works_by_dois`），补上 `openalex_id`、arXiv 编号、PDF 链接（与百度页面合并，互不抹掉）和语言；只有 arXiv 或期刊开关至少开着一个时才发这次请求。标题和摘要始终是百度的。OpenAlex 已经找到的同一篇只加上百度页面。
  - 语言：百度不报告语言，所以保持“未知”写入数据库，不写 `metadata_language`；评估时与英文摘要兜底相同，仅在来源没报告时按标题（至少 4 个汉字且占多数、无假名和韩文字母）和摘要（有真实摘要时汉字至少 10 个且占字母的十分之一）判断为中文，不写回。OpenAlex 补全后存下的语言优先。只有英文的项目从不查百度；只有中文的项目用 `language_not_allowed` 丢掉英文的百度论文。
  - 资格：只有百度页面的论文算 `page`（有来源），仍需要摘要；只有 DOI 不算来源。来源开关统一走 `SourcePolicy`。
  - PDF 路线：`source_adapters.pdf_routes` 的顺序是 arXiv PDF（自动）→ OpenAlex 的 https PDF 链接（自动）→ OpenAlex 原文页面 → 来源页面（百度，可能要登录）→ 出版方页面（DOI，可能要登录）；`download_pdf` 在没有 OpenAlex 的开放获取事实、但有 OpenAlex id 或 DOI 时用公开元数据查一次（有 id 用 id，否则用 DOI），把结果合并进 `oa_json` 再重试 PDF 链接。仍失败时返回 `pages`（百度页面、OpenAlex 原文页面、出版方页面，各带 kind/label/url/needs_login），`landing_page` 保留给旧调用方，只要有任一页面原因就是 `landing_page_only`（以前只有开放获取且有原文页面时才是；对应的一条旧测试按此改了）。阅读器只显示一行原因、至多 3 个页面按钮（第一个为主按钮）和一个“选择或拖入 PDF”；整个阅读区接受拖入的 PDF，经 `/api/seeds/pdf` 和 `/api/pdf/attach` 附上。不监视下载文件夹。
  - 链接：卡片、详情、论文库和创建页的论文链接按 arXiv → DOI → OpenAlex → 来源页面（百度）取第一个。
  - 学习图（beta）的刷新**没有接入百度**：它自己规划检索（见 ADR 0016），不是顺手能接的，所以不接并在此说明。
- **单元 C**（创建项目与种子检索）：
  - 创建项目的候选论文（`guidance_search`、`guidance_preview`）：页面把勾选的论文语言随每次检索请求发来（`languages`）；百度开关打开、已配置密钥、**勾选了中文**且检索式含汉字时，每条检索式再问百度一次（第 1 页，最多 10 条，窗口外的年份按“全部年份”开关处理），结果与 OpenAlex 结果合并成同一份候选列表（同一个 DOI 只算一篇，补上百度页面）。百度出问题时返回里多一个 `baidu: {kind}`，页面只显示一句短状态（“百度学术：今日额度已用完/密钥无效/无法连接/暂时不可用”），OpenAlex 结果和页面照常；这里**不做** OpenAlex 的 DOI 补全（候选只是给人挑，PDF 链接和语言在以后需要时再查）。
  - 种子检索（`seed_search`）：开关打开、已配置密钥、输入含汉字时再用输入的标题问百度一次（只发用户键入的文字），两个来源的结果按标题与输入的吻合程度排序后合并，百度命中带 `seed_id`。百度命中可以加为种子：有 DOI 就用 DOI（先问 OpenAlex，OpenAlex 没有这个 DOI 才用记住的百度命中），没有 DOI 的用 `baidu:<id>` 标识（标识只对本进程里刚搜到过的命中有效，没搜到过的报“找不到”，不影响项目创建）。百度失败时返回 `baidu: {kind}`；两边都没有结果才算没找到。
  - 额度：创建和种子检索与每日推送共用同一个每日 40 次的计数和 24 小时缓存。

- **审查修复**（单元 D，独立审查后）：百度页面链接的校验改严（反斜杠、`@`、百分号、非 ASCII/带端口的主机名一律拒绝，主机名小写化，因为浏览器按 WHATWG 规则读 `\` 为路径分隔符）；翻页游标不再把“按年份窗口过滤后为空”当成“这一页为空”；只开百度、关掉 OpenAlex 的两个开关时，开发用的 distractor 探测和学习图刷新不再碰 OpenAlex；拖入的 PDF 里读出的标题不再发给百度（只有用户键入的标题才发，页面请求带 `typed: false`）；缓存前递归剔除任意深度的 `aiAbstract`；密钥文件用独占创建的唯一暂存文件写入（`O_EXCL`、不跟随链接、0600），清除时一并删掉残留的暂存文件；已有的百度论文行被 OpenAlex 补全后也会补上空的 `openalex_id`/`arxiv_id`（只补空白，不替换）。仍存在的一个歧义：以 DOI 为键、没有 `openalex_id` 的论文（例如导入时没查到 OpenAlex 的）若后来百度也报告了它，就只受百度开关控制。

## 后果

- 百度结果没有作者，只有年份（`published` 记为该年 1 月 1 日，年份 0 视为未知），顺序是百度的相关度，不是日期；同一关键词每天换一页（单元 B）。
- 百度学术页面往往要登录，所以应用只展示、不抓取；PDF 仍靠 DOI→OpenAlex 的开放获取链接，否则由用户在浏览器里取得 PDF 后拖进阅读器。
- 额度用完只暂停百度，不影响其他来源，也不自动加价。

## 未验证项（保持可见）

百度响应的全部字段名与类型、错误码形状（现在按信息文字分类）、密钥格式（现在允许字母、数字和 `. _ ~ + / = : -`）、千帆密钥页面的地址（`SourceInfo.key_url`）、日界时区、超额是拒绝还是计费、`aiAbstract` 是否默认返回、分页是否从 0 开始、每页条数。`tools/source_smoke.py` 用真实密钥跑一次即可核对，之前所有解析都是容错的：缺字段、列表或标量、未知字段都不会崩。

## 不变

不加后端、遥测或云同步；所有模型调用仍走 Gateway，本功能不调用任何模型，核心路径零模型 token；原件、来源引用不改；不从“没点”推断不喜欢。

## 增补（2026-10-23）：百度 AI 搜索限定百度学术站点（`baidu_web`），第二个百度来源

**为什么**：2026-10-23 的真实检查（[证据](../evidence/2026-10-23-baidu-live-checks.txt)）表明，百度学术工具（`GET /v2/tools/baidu_scholar/search`）对 owner 的账号返回“404 page not found”，文档里的路径与一条编造的路径表现相同；同一把千帆密钥调用百度 AI 搜索（`POST https://qianfan.baidubce.com/v2/ai_search/web_search`）返回 HTTP 200，加上 `search_filter.match.site ["xueshu.baidu.com"]` 后返回了近期的中文论文。owner 原话：“先加上百度搜索限定百度学术的通道，试一下这个吧，看看可以不”。

**数据外发与批准**：与上面已批准的百度学术完全相同的数据范围，批准沿用 owner 2026-10-23 的原话——“中文关键词发给百度”（含汉字的项目关键词、创建项目的检索式、键入的种子标题，用 owner 自己的千帆密钥）、“每天最多 40 次”、“百度页面算“需要登录”的来源”，范围“一次全接”。没有新增任何外发内容；只是多一个端点。`owner_approved` 仍是 false，不由 agent 自填。**待办（owner）**：百度 AI 搜索免费额度是每月 1500 次，之后按量计费；“限定站点”被文档标为付费功能、目前限时免费——请保持计费关闭，或在千帆控制台确认超额的处理。

**决定**：

1. 新适配器 `app/baidu_web.py`（`SourceInfo.id = "baidu_web"`，标签“百度学术（百度搜索）”）。它**共用百度学术的千帆密钥**：`SourceInfo.key_shared_with = "baidu_scholar"`，`source_keys` 把它的密钥文件、环境变量（`BAIDU_SCHOLAR_API_KEY`）和格式都解析到百度学术那一把；设置页的“百度学术”块只有一个密钥行（密钥框、状态词、测试、清除、获取），下面两个开关“百度学术接口”和“百度搜索”（只是复选框，默认关闭）；密钥行的状态词和“测试”针对 `baidu_web`（一次请求，计入同一个每日计数），因为百度学术工具对有的账号永远返回 404，主测试按钮不应该看起来是坏的；`/api/source-test` 仍能测 `baidu_scholar`；保存或清除密钥会同时更新两个适配器。第一次打开开关时用同一个一次性确认（`baiduScholarConfirmed`，文案点明含中文关键词会通过百度搜索发给百度学术）。
2. 请求只含 `messages`（单轮，查询最长 72 个单位，汉字算 2）、`search_source "baidu_search_v2"`、`resource_type_filter [{type: web, top_k}]` 和 `search_filter.match.site ["xueshu.baidu.com"]`；只有 owner 选了时间范围（设置里“时间偏好”为最近/一个月）时才加 `search_recency_filter`（week/month），“全部”或没选就是没有过滤——否则时效只是排序权重。top_k：每日推送 20、创建候选 12、种子 8。不请求网页以外的任何资源，不发 `edition`，不用 `range` 时间过滤。密钥仍只作为不可重定向的请求头发给 `qianfan.baidubce.com`（https）。
3. 解析：`content` 形如“题名 来自 站点  喜欢N 阅读量: N 作者: … 摘要: … 关键词: … 年份: …”，取作者、摘要、关键词，去掉题名和计数噪声；没有 `摘要:` 标记时，剩余文字至少 40 个字符才当摘要。作者能读出来，但 `papers` 表没有放作者的地方，本变更不加迁移，所以不存。专利（有“申请(专利)号”“发明人”）不是论文，略去。键是 `baidu:<paperid>`（取自页面链接，与百度学术的无 DOI 键同一命名空间），`published` 优先取内容里合理的“年份”（该年 1 月 1 日；`date` 同年时保留完整日期），因为 `date` 很可能是页面日期（真实样本没有时间过滤，7 个日期都在 16 天内；**含义未验证**），没有“年份”时才用 `date` 的日期部分，没有 DOI、期刊，不报告语言，页面链接只收 https 的 `xueshu.baidu.com`（复用同一个链接校验，含反斜杠、`@`、百分号、端口一律拒绝）。`oa.via` 总是 `["baidu_web"]`（没有页面时 `pages` 为空），这样来源开关始终管得到这篇论文。
4. 额度与缓存：owner 说的“每天最多 40 次”是对这一把千帆密钥说的，所以**两个百度来源合计 40 次**，共用同一个每日计数 `source_usage:baidu_scholar:<日期>`（北京时间；沿用原来的键名，已有的计数不丢），请求前同一条原子语句预留，第 41 次（不管哪个来源）在发出之前就被拒绝；缓存命中不占额度，失败也计数，不重试，设置页“测试”和 `tools/source_smoke.py` 也花百度的额度（后者不计入本地次数）。24 小时缓存按请求内容（含站点、top_k、时间范围）的哈希命名，缓存里每条保留页面、题名、日期和完整的 `content` 文本（其中含作者姓名），不留 `markdown_content`、`snippet` 等。状态记在 `source_status:baidu_web`。HTTP 429 是每秒请求数限制（暂时性，按“服务暂不可用”处理），只有响应正文点明是每日额度才算“今日额度已用完”；错误信息里的限额/频率词按整词匹配。
5. 接线：和百度学术相同的三处（中文项目且有含汉字关键词的每日推送；勾选中文的创建候选；键入的种子标题），每处只在 `sourceBaiduWeb` 打开且共用密钥已配置时才问。两个百度来源都开时两个都问，按 `baidu:` 键和标题（忽略大小写、空格和标点）去重，后到的那篇只给先到的补上自己的页面；百度学术“服务暂不可用”（现在对 owner 的账号就是这样）不会阻止网页搜索，反之亦然。创建/种子页的那一句状态（`baidu: {kind}`）只在被问到的百度来源**全部**失败时出现，并取最可操作的一种：密钥无效 > 今日额度已用完 > 无法连接 > 其余（暂时不可用最后）；某个来源抛出意外异常也只算它自己失败，不会中断刷新、检索或种子查找；题名只剩标点（比较用的标记为空）的论文不参与题名去重。来源开关：`SourcePolicy` 按 `oa.via` 判断哪个百度来源报告了论文，只由网页搜索报告的论文只受 `sourceBaiduWeb` 管，两个都报告过的任一开着即可，没有 `via` 的旧 `baidu:` 键仍算百度学术。
