# ADR 0034：整理分类按左侧目录范围、未分类优先且不留尾巴、方案逐项可选

2026-10-09。业主反馈：整理分类的对象应是左边目录里显示的（项目标签只整理该项目，“全部项目”整理全部）；先处理未分类论文，整理完不能还有未分类，然后才是调整/合并；预览只有一堆列表，按钮写“应用所选”却没有地方选。修订 [ADR 0027](0027-category-standards-review.md) 的范围与应用方式，不改变其安全底座（完整预览确认、一个事务、一个撤销事件、取消/未知用量/并发变化失败关闭、AI 只给意见）。本单元的独立审查（7 项 major、9 项 minor）及处置见[审查记录](../evidence/2026-10-09-organize-scope-review.md)，下文已按其结论修订。

## 决定

1. **范围 = 左侧目录**。项目标签下，冻结的论文是该项目已收藏论文，冻结的类别是页面左侧目录显示的类别：与页面同一规则——已被论文占有（本类或子类）但没有任何本项目论文的类别，连同其子类，都不显示、不发给 AI、不被改动；没人占有的空类别保留。“全部项目”标签仍是全部论文与全部类别。规则在 `category_review_units.scope_directory`；它与前端 `otherProjectCategories` 共用同一份用例 `tests/fixtures/scope_directory_cases.json`，Python 与 Node 各跑各的实现，期望值只有一份。
2. **共用类别只接收论文**。项目范围内，一个类别若被本范围之外的论文占有（别的项目、已归档、不属于任何项目），或被“另一个项目也收藏了的”本项目论文占有（页面的“跨项目”徽章），或带有被隐藏的子类，就是共用类别；**它的所有祖先同样锁定**（合并/删除上级会移动共用的子类）。共用类别只能 keep，仍可作合并目标、新类别的父类和论文归属。提示词用匿名 `"lock":1` 告知；`parse` 对仍然提议改动的**丢弃该条提议**（整份回复其余部分有效，不让一批付费调用因此作废）；`_safe_plan` 与最终写入口 `_apply_ai_review`（锁由库内数据重新推导，不信任方案）再独立拒绝。
3. **看不见的同名类别**。模型看不到只在其他项目里的类别，所以：它提议的、与某隐藏类别同层同名的新类别，改为让论文并入那个已有类别（映射反复进行至不变，与回复里父子顺序无关）；它提议的、会与隐藏类别同层同名的改名，丢弃该条改名；它提议的合并若会让被并入的子类与目标下某个隐藏子类同层同名，也丢弃该条合并（均以 `stats.kept_by_scope` 计数）。丢弃只影响那一条提议，整份方案其余部分照常。**丢弃可能让依赖它的另一条提议变得不能应用**（例如合并到一个其改名被丢弃的目标）：方案成形后先在库上只读试应用（`Organization.plan_error`），不行就从“没有任何类别变更”的方案出发（它必须能应用），把各条提议按原顺序逐个加回，能应用的都保留，所以互不相关的提议不会被连带丢掉（只丢类别变更，绝不丢论文归属，尤其不丢“归类未分类”），连这个基线都不能应用才在存方案时报错（`stats.demoted_for_validity` 计数）；整个过程是本地的，不重复任何模型调用。
4. **未分类优先**。冻结队列把未分类论文排在最前；提示词把“每篇未分类论文归入至少一个最终类别”列为第一优先，调整/合并/删除与已分类论文的归属排第二。预览同样先列“归类未分类论文”，再“调整现有分类”，最后“重新归类已分类的论文”。
5. **不留尾巴**。提示词要求每篇至少一个类别；`parse` 仍容忍空数组（保持“整份回复严格校验”的既有合同），随后服务层本地兜底：**已有类别的论文**模型返回空时，保留它现有的类别（经方案的合并映射、去掉被删的）；只有没有任何类别可留的论文才进顶层“其他”（已有则复用，英文界面为 Other），标记 `fallback` 并在预览写“依据不足，暂放”。新建“其他”和 AI 新建类别的 ID 若与现有类别冲突（例如更早一次整理建的类别后来被用户改名/移动），换用加盐的新 ID，不让后续整理永久失败；与可见类别冲突的在别名阶段就加盐（那时模型对“已有类别”和“新类别”的引用还是不同别名，论文不会被并错），与隐藏类别冲突的在整份方案成形后、复用映射之前加盐。`_safe_plan` 再断言不存在空归属。兜底零模型 token。用户在预览里取消某些论文的勾选是他们的明确选择，应用结果如实写“仍有 N 篇未分类”。
6. **逐项可选**。服务端把方案拆成可选单元（`category_review_units.build_units`）：每篇需归类/需移动的论文一个单元，每个改名/合并/删除一个单元。仅由类别操作引起的论文变化（合并会带走论文；删除连同其论文的改归一起）不单列。依赖由服务端保证：删除某类别带上它的论文改归；删除父类带上处理其子类的单元；新类别只在被已选论文使用时才创建（及其新建祖先）；**其余依赖不靠枚举规则，而是试出来**——存预览时对每个类别变更、每一对类别变更，以及“带新类别的论文（每组新类别取一篇）单独和与每个类别变更一起”，在库的私有副本上试应用（`Organization._offered_units`；论文单元若不引用新类别不可能单独失败，不试），单独或成对不能应用的就与能使它成立的单元绑在一起（先试补一个类别变更，再试全部类别变更，最后是整份方案），写入单元的 `requires`（“论文组 × 类别变更”这类试跑在两者乘积超过 600 时不再做，交给应用时的兜底；带新类别的论文与类别变更的冲突，补救挂在类别变更一侧，不让“归类未分类”这个第一优先级的单元被拖上别的改动）；应用时使用同一份已存单元。典型例子：两对重复父类各带同名“Planning”子类，合并父类必须同时合并子类；计划删除英文“Robotics”并把论文归入新建的“机器人”，则只勾归类也会带上那条删除。**高阶组合（三个及以上类别变更互相牵连）无法靠预先试出全部**，所以应用时还有一道兜底：先取所选及其依赖，若在当前库上仍不能应用，就补上最少的类别变更（先试补一个，再逐个累加，最后是整份方案——已被完整校验），**并在结果里报告另带上了哪几项**（页面提示“为保证能一起应用，另带上了 N 项整理内容”，可撤销）。因此页面提供的组合应用时不会因此失败，也不会悄悄多改；随机方案×全部子集的压力测试里需要兜底补齐的不到 2%。`apply-ai-review` 接受 `selection:{units}`，生成自洽子方案后走同一个 `_apply_ai_review` 全量校验；不带 `selection` 时仍应用整份方案。空选择、未知单元被拒绝且不消耗预览。方案是一次性的：未勾选的项目需要重新整理。页面勾选联动与服务端 `requires` 同一规则；应用进行中勾选与按钮被锁，避免重复提交；报错放在随滚动保持可见的底部操作栏里。
7. **同层同义检查只看本方案动过的类别**。此前任何两个同层同义类别都会让整份方案失败，范围收窄后一个项目看不到的旧重复会让该项目永远无法应用；现在只检查新建、改名、因合并换了父类的类别。新建/改名仍不能制造同层同义。

## 预算与隐私

单批上限不变（输入 8000 字节保守预检、输出 2000，每批一次、无重试、无推理或模型替代），未提高任何额度，未新增外发内容：新增的只有匿名的 `"lock":1` 标记，不含私有 ID、画像、笔记、反馈。提示词变长 269 字节（2683→2952），靠压缩旧措辞把“60 类×12 篇空文本”极限用例压在 7900/8000（基线 7629）。可复现测量（脚本与输出见[检查证据](../evidence/2026-10-09-organize-scope-checks.txt)；英文标题 80/摘要 160 字符、类名 6 个汉字、全顶层、全未分类，每批最多 12 篇）：每批可放论文数 0 类 12→12、10 类 11→10、20 类 9→8、30 类 7→6、40 类 5→5、50 类 3→3、60 类 2→1；中文摘要 160 字时 20 类 5→4；零论文时能放下的最大目录（类名 12/20/30 字）56→53、43→41、34→32（6 字仍是 60）。即常见规模下每批少放 0–1 篇、目录很大时批数更多，且类名很长的 53 类以上目录会被拒绝（此前到 56 类）；每个被锁类别另加约 11 字节。项目标签下目录更小，通常缓解此影响。这是预检算术，不是账单或 tokenizer 实测；输出 2000 token 对 60 类加新类别理由是否够用未测。

## 未做与限制

- 本地（无 AI）检查路径不改：它只在 AI 失败/未开时作为后备，仍可能留下“待归类”并提示“用 AI 帮我归类/手动新建”。
- 类别结构意见仍由第一批决定并冻结给后续批次（沿用 ADR 0027），没有让后批看到前批新建的类别；第一批可能只含未分类论文，那时结构意见只依据类名。大量未分类论文会在各批独立命名，靠规范身份合并同名，近义不同名的新类别可能并存，待用户在预览里取消或事后手动合并。
- 方案一次性：部分应用后结构变化使预览失效，未勾选的项目要重新整理（再次产生一次整理调用）；撤销之后预览同样不再可用（撤销会清掉临时预览），也要重新整理。
- 被丢弃的越权合并/删除（锁定类别）所涉论文的移动仍留在预览里：它们作为“重新归类”单元可见、默认勾选、可取消，但预览里不会标明模型原本想合并。
- 存预览时的试跑只试类别变更（及其两两组合，类别变更不多于 40 个时），不逐篇试；实测 27 个类别变更、3000 篇论文约 1.4 秒。旧版留下的、没有可选单元的预览不会被补算，页面提示重新整理。
- `prompts/category-review.md` 文字已改但 `status: owner_approved` 与批准语未动：授权范围/上限/隐私口径（单批 8000/2000、显式触发、无重试、不外发私有数据）没有变化，但新措辞需要 owner 知悉；本单元没有也不能自行改任何批准字段。
- 真实模型质量、真实库、原生窗口、8GB 资源未测；未调用任何真实模型。
