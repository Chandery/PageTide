# ADR 0047：在应用里下载（像浏览器一样，由人打开）

2026-10-26。owner 看到阅读器说“这个网站只允许在浏览器里下载”，问：“这种不是说已经可以了吗，跟 CNKI 一样，用模拟浏览器去下载啊，不要用爬。”

## 实测（同日，探针在 `.local/probe/pdfprobe.swift`，不在仓库里）

用与 Tauri 相同的 WKWebView（macOS）写了一个小窗口：

- WKWebView 能显示 PDF，所以 PDF 链接在窗口里直接显示，不触发“下载”（wry 只对不能显示的类型改为下载）。
- PDF 显示在窗口里时，注入的脚本照样运行（document start 的 user script 在 PDF 文档里也跑），页面里的 `fetch(location.href)` 用窗口自己的会话拿到完整 PDF：arXiv 765,699 字节、IOP（`iopscience.iop.org/article/10.1088/2634-4386/aeaf13/pdf`）2,987,108 字节，开头都是 `%PDF-`。
- 同一个 IOP 链接，应用后端的下载（Python）被转到 Radware 人机验证页（`validate.perfdrive.com`），窗口里的浏览器内核直接拿到 PDF，没有出现验证。

## owner 的决定（对话中选择，原文选项标签）

1. 怎么开始：“**A button you click (Recommended)**”——阅读器失败页上的主按钮“在应用里下载”，点了才打开窗口。
2. 窗口能去哪里：“**Only the paper's own pages (Recommended)**”——从论文自己的 PDF 链接或原文页开始，可以跟随页面上的链接和跳转；独立的网页存储，与应用分开。

## 做法

- 外壳（`src-tauri/src/pdf_window.rs`）开一个可见窗口 `pdfdl`：只允许 https、公网主机（拒绝 http、localhost、内网地址、自定义协议）；新标签页链接在同一窗口打开；独立的网页数据存储（Windows 单独目录）。
- 窗口里的脚本（`pdf_window.js`）只在窗口显示 PDF 时工作：用窗口自己的会话读一次这个 PDF，按 1 MB 分块交给外壳（`pdf_window_chunk`，base64）。网站以“下载”方式给的 PDF（Windows 的 PDF 查看器不运行页面脚本，点它的保存就是下载）也接住：下载写到系统临时目录，读完即删。
- 外壳只接受一件当前任务、不超过 60 MB、开头是 `%PDF-` 的文件；主页面轮询到“已收到”后取走字节（`pdf_window_take`，二进制），按“拖入 PDF”同一条路交给服务端：完整校验 PDF、存进论文库的 `pdfs/`、附到这篇论文上，然后关窗、打开阅读器。人关掉窗口，主页面就停止等待；阅读器换到别的论文时窗口自动关闭；30 分钟没拿到就结束。
- 命令按窗口分开授权：主页面的 `pdf_window_open/poll/take/cancel`（与其他应用命令同样的来源检查）；下载窗口只有 `pdf_window_chunk`，授权给标签为 `pdfdl` 的窗口里的任何 https 页面。

## 边界

- 窗口里任何网页都能调用 `pdf_window_chunk`，最坏情况是网页交来另一份 PDF：它仍要通过服务端的 PDF 校验，附到的是人自己打开的那篇论文，人在阅读器里看得到。网页拿不到应用的任何数据，也调用不了别的命令。
- 不自动通过任何验证；不在后台运行；不伪装浏览器之外的任何东西（窗口本身就是系统的浏览器内核）。用户点开的下载已不读 robots.txt（ADR 0011 补充），窗口同理。
- 关闭下载窗口只关闭它，不会退出应用（之前关闭非知网窗口会走退出流程）。

## 没验证的

- Windows（WebView2）没有真机测试：PDF 查看器里脚本可能不运行，此时要靠人点查看器的保存按钮触发下载被接住；这条路径没有跑过。
- 需要登录或机构订阅的出版社、会弹出人机验证的网站，都只在设计上支持（人在窗口里完成），没有实测。
- 知网的 PDF/CAJ 下载（需要校园网）没有试过。

## 补充：文章页上的 PDF（同日，owner 实测后）

owner 第一次试的论文（DOI 跳到 cyberleninka.ru）不是直接给 PDF，而是在文章页里内嵌一个阅读器，脚本因此什么也没做。几乎所有出版社都在文章页写 Google Scholar 用的 `<meta name="citation_pdf_url">`：现在文章页上有这个标签时，脚本用窗口自己的会话读那个 PDF 并交出；浏览器不允许读（别的网站）时，窗口转到那个地址一次，变成“窗口显示 PDF”的情况。

## 独立审查（同日，只读、另一个 agent）

没有高严重度问题：两个窗口的命令授权互相隔离，iframe 调不了命令，没有持锁调用窗口的地方。已修正：下载路径不查地址和大小（现在只接受允许的地址和 blob:/data:，一次一个，先看文件大小再读，读文件不持锁，任何情况都删临时文件，只在任务仍在等待时收下）；`window.open('')` 先开空白窗口会把当前页冲掉（新窗口请求只接受 https）；几种写法的本地地址能通过（IPv4 映射的 IPv6、NAT64、0/8、100.64/10、组播、广播、.lan、.home.arpa）；取消时不带论文（现在只取消这篇论文的任务）；取字节失败没有提示。

接受的风险：窗口里出现的第一份 PDF 会被直接收下（人点开的补充材料、或页面上第三方脚本交来的 PDF 也会），服务端仍做完整校验，附到人打开的那篇论文上，人在阅读器里看得到；单次 IPC 消息的大小在 Tauri 反序列化之后才检查；窗口的地址限制对所有框架生效，用 http、blob、data 的内嵌查看器或弹窗式机构登录可能用不了。
