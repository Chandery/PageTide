# ADR 0029：导入已有论文库（PDF 单篇/文件夹/Zotero 导出）

2026-10-07。业主要求：已有成熟论文库的用户不必用学习模式重建；新建项目时和之后在论文库里都能导入；形式为单篇 PDF、整个文件夹，以及后续的 Zotero；导入后能按原有结构自动整理。

## 决定（业主 2026-10-07 逐项确认）

1. **角色**：导入的论文进入项目论文库（`project_papers.relation_kind='imported'` + `project_library`），**默认不是任何兴趣信号**：不写 feedback/exposure，不改 `seed_keys`。完成页可把其中已识别的论文设为种子，单次最多20篇、项目总计40篇（与创建时上限一致）。导入来源的种子记入 `import_seed_keys_<project>`：进画像和排序，但**不是生长证据，也不推进学习地图进度**（ROUTE-V2-06“导入不算证据”）。后一半（不推进进度）是实现时对规则的延伸，等业主确认。种子仍参与发现：路线召回会用种子的公开标题/主题词向 OpenAlex 检索（`_route_recall_interest`），导入来源的种子也在内——这是设为种子的本意，不是生长证据。
2. **PDF**：复制进应用归档 `pdfs/import-<sha24>.pdf`（按内容寻址去重），原文件不动；不覆盖论文已有的当前 PDF，除非业主在导入选项里勾选替换（旧版本留在 `pdf_versions`）。来源记为 `source_kind=user_import`、`source_url=user-import:batch/<id>`。
3. **自动整理**：默认零 token——子文件夹层级（最多3级、名称≤60字）直接成为分类；同层同名（`category_identity`）复用，成员只追加，标记 protected，整次导入一条可撤销事件“导入分类”。AI 复审沿用已批准的 `category_review`，由用户在论文库点「整理分类」触发；导入本身不新增任何模型操作，导入页只给出批次估算和提示，没有预算预检（`run_review` 不改，见开放风险）。
4. **Zotero**：只走“导出（含文件）+ 文件夹导入”：BibTeX / RIS / CSL-JSON，元数据直接读导出文件；不读 `zotero.sqlite`、不用本地 API、不写回 Zotero。导出文件夹本身可作为一个顶级分类（每个 collection 分别导出）。READ-02（本地 API/写回）仍 blocked。
5. **推荐池**：已在本项目论文库里的论文不再是今日/路线候选（仍留在检索与画像语料中）。这是为避免整库导入后被当成“新推荐”推回，同时修正了此前“已保存但未评价”的残留。引导创建选中的候选虽也是 `imported`，但没有保存，仍可被推荐。
6. **联网补全元数据默认开启，页面写明发送什么**：只有从 PDF/导出文件识别出的 DOI、arXiv 编号和论文题目发给 OpenAlex；PDF 文件、论文库、笔记、画像不外发。关闭后导入本身不会联网，未识别的 PDF 按原样入库；只有用户在确认页里主动「查找」时，输入的文字才会发给 OpenAlex（用户自己的查询，页面写明）。

## 数据与流程

- 惰性建表 `import_batches`、`import_items`（`CREATE TABLE IF NOT EXISTS`，先例 `org_drafts`），不占迁移号，避免多分支共享真实库时撞号（ADR 0011 §10）。外键级联；删除项目清理暂存目录和 `import_seed_keys`。
- 页面读 PDF 首页（pdf.js，与创建页共用 `pdf-hints.js`）得到 arXiv/DOI/标题线索，逐个流式上传到 `imports/batches/<id>/`；服务端后台线程按节奏匹配，进度写库，关页/重启可继续。审阅后一次提交：一个 `BEGIN IMMEDIATE`，失败整体回滚并清理本次新写的文件。
- 匹配顺序：导出文件的 DOI/arXiv → PDF 线索 → 文件名中的 arXiv 号 → 库内已有（同 sha、同 DOI/arXiv）→ 标题。导出条目有自己的记录：不按标题检索；OpenAlex 不认识或拒绝请求时保留导出文件的记录，摘要为空时用导出文件的摘要。标题相似度≥0.8、比第二名高出至少0.05、且标题至少两个词才自动接受，否则最多5个候选由用户选（同名的预印本与正式版因此会询问）。PDF 首页读到的 DOI/arXiv 号可能是被引用论文的：若 PDF 自己读出的标题（≥3词）与匹配到的论文标题几乎无共同词（相似度<0.25），改为“需选择”而不是静默接受；导出文件来源不做此检查。
- 同一次导入里两个不同 PDF 匹配到同一篇论文：第一个成为当前 PDF，其余默认不归档、不替换（原文件没动），完成页点名；勾选“替换”时依次记录、旧的留在文件历史里。
- 识别不了的 PDF 以 `pdf:<sha256>` 为键入库，没有摘要，因此不会被推荐；导出里没有 PDF 的条目默认不导入（可勾选），键为 DOI URL 或 `entry:<hash>`。
- OpenAlex 配额是真正的限制：每次检索 10 点，无 key 每天约 1000 点。DOI 每 50 个一批；额度不足、限流、断网时**暂停**而不是失败或把全部标成未识别，用户可随时选择“不再联网，按原样导入剩下的”（不发送任何内容）。服务器明确拒绝整批请求（HTTP 4xx，非限流）时不当作断网：逐个 DOI 重试，只让出问题的那一个失败。同一时刻只有一个批次在匹配（跨进程锁），另一个批次会暂停并说明原因。

## 失败路径与边界

- 单文件 ≤60MB、单批 ≤2000 个、磁盘余量检查；相对路径规整（NFC、折叠空白、拒绝 `..`；两个只差空白数量的同名文件会被视为同一路径，后者替换前者——已知的小限制）；导出文件 ≤20MB、≤20000 条、嵌套深度有上限，解析为线性时间。未提交的批次 30 天后自动清理；中断的上传可在“补传并继续”里只补缺少的文件，中断的提交可“重试提交”，上传失败的文件在确认页列出并可补传。
- 同内容的多份副本合并为一条，所在的每个文件夹都成为分类；导出条目命名的是某个副本时也能对上。仅在带导出文件的批次里，Zotero 的 `files/`（及其数字子目录）首层不成为分类；误选的 storage 目录名同样不成为分类。普通文件夹里的 `files/2023` 是用户自己的结构。
- 无服务端 PDF 解析器：扫描件读不出文字时仍入库为未识别 PDF。
