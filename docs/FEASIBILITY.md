## 预算和资源的重新评估口径

- 首轮推荐画像提案不用生成模型，也不下载本地神经权重，计划模型调用为0。其真实成本是元数据 API 请求、CPU/RSS/磁盘与时间。
- AI 速览/追问/周报/划词是独立可选层，token 与 USD 提案已登记：核心无 AI 为 0 token/天；仅开每日速览 + 周报参考约 4,500 token/天、上限约 10,800/天，月度上限约 19.2 万。未批准、未实测，见 [BUDGET](BUDGET.md)。
- 不沿用旧每日五卡/问答/周报的月token估算作为承诺。旧操作配置已清空后再按新操作重新登记，当前 `approved_by_owner=false`。
- 先确定需要哪些请求、语料规模和使用频次，再测计算资源与数据费用；选型前不给一条看似精确的“每月最低成本”。
- 当前开发机记录为M4/24GB，8GB仍是暂用目标；新核心的内存/延迟阈值需在试验前确认，不继承旧阅读器峰值当作通过。

## 目前可说和不可说的结论

可说：有现成代码可显著减少自建范围；先验证推荐与画像闭环比先实现阅读器更贴近产品目标。

不可说：已选定一个开箱即用底座、推荐精度达标、画像更新会提高质量、Mac低配性能通过、全部开源依赖无风险或模型费用得到控制。本轮未运行候选，质量和资源gate均为not_run。

下一步先取得领域与种子、确认实验，再做受限复用探针和数据覆盖验证。详见活跃 `PLAN-02`、`REUSE-01`、`DATA-01`；旧A任务停止执行。
