## Route 批次分配（2026-10-07，阶段 05）

学习期间每批最多三篇路径、一篇探索、一篇新进展。发现内容先相互补位，再由路径补位；路径不足允许少推，发现始终最多两篇。候选兼任多个用途时，先保留不同论文可组成的三种位置。已满足而未关注的常规论文不补学习任务；“太难”不会自动重新推已满足前置。未回答路径论文按曝光少的优先轮转，显式回答后退出。

目标完成后每个项目每个本地日期最多生成一篇发现，探索优先，持续关注的新进展次之。手动与自动维护共用同一事务限制；重复点击显示当天已有批次，不新增曝光，也不再次自动速览。无候选、没有前沿、图需要检查分别说明，Route 开启时不退回普通排序。

探索来源只是新任务、前置缺口或分支的线索。它可以匹配已有概念，学习价值仍待确认。新进展必须未展示、未回答，属于已满足且持续关注的概念，并有有效近期日期。两种发现均不会自动修改学习图或调用新的模型。

卡片的学习归属和进度都采用最强概念匹配。已有反馈、种子或曝光的无摘要论文可用当前 PDF 的有界正文匹配；改变推荐语言不撤销读懂证据。版本与正文改变使首页进度重算。未完成的正文核验不缓存为最终进度，页面显示核验中并阻止新批次。一次生成各环节共享正文物理核验预算，耗尽后可在下次继续。

## Route 候选召回（2026-10-07，阶段 04）

Route 刷新在同一个三主题上限中分配当前学习路径、目标边缘探索和已满足且持续关注的新进展。主题轮转，路径和探索满页后翻页，关注检查最新第一页。相同检索词也按用途的检索策略分别保存页码；只拖动布局不重置抓取状态。来源信息有界保存七天，用于解释本次发现，不改变论文原有类别或种子归属。

并发刷新会检查输入和已保存状态，旧结果不能覆盖先提交的新结果；论文与来源一起保存，失败一起回滚。日常核心新增模型调用为0，仍只发送公共检索短语。详见 [ADR 0016](decisions/0016-bounded-route-recall.md)。3+1+1批次、完成后每日上限和生长提议继续由后续阶段实现。

## Route 目标状态与持续关注（2026-10-07，阶段 03）

当前目标范围是活动目标及其活动前置祖先；多个目标合并计数，旁支不阻止完成。`goal_done/goal_total` 表示目标范围，旧 `done/total` 保留全图口径用于历史兼容。当前前沿只取目标范围内已解锁但未满足的概念。所有目标范围概念满足后才完成；缺失目标、范围内缺失前置、循环或不完整进度进入“需要检查”，候选论文不足不会被当作完成。

“持续关注”是独立开关。可以在学习期间先关注，不改变掌握；只有已满足且被关注的概念才有资格进入新进展候选。开关随项目和概念身份保存，关闭 Route、重启和撤销后保留；删除或用同一 ID 替换成不同概念时不转移关注。未保存编辑不允许关注操作；保存冲突后，干净页面显示新图，编辑中的草稿保留供检查。

这些状态由本地规则计算，新增模型调用为 0。三类召回见阶段04；3+1+1 配额及完成后每日一篇仍由阶段05实现。见 [ADR 0015](decisions/0015-route-goal-watch.md)。

> **界面名称（2026-10-06 起）**：顶栏只有 今日 / 论文库 / 画像。“论文库”页（原“论文整理”，顶栏曾另有一个“知识库”入口，指向同一页）里切换 **列表 | 图谱**（原“论文库 | 知识图谱”）；图谱里是 **论文关系 | 学习图**；原“整理建议”叫 **整理分类**。下文及更早的记录按当时的叫法保留，不逐条改写。

## 1. 主体是什么

PaperDigHelper 的主体是：**根据你的研究问题推荐值得看的论文，并根据你明确给出的反馈维护可解释、可修改、可撤销的用户画像。**

最短闭环：

```text
研究问题 + 少量种子论文
  → 候选论文与来源覆盖
  → 推荐列表、推荐依据、未知之处
  → 有用 / 不相关 / 以后再看 / 没空 / 看不懂
  → 可查看的画像变化与撤销
  → 下一批推荐，对比是否真的改善
```

没有 PDF 浏览器也应能验证这条闭环。阅读通过论文网页或已有软件完成；不需要先搬迁论文库、导入全文、写插件、实现笔记系统或完成 API 校准才能开始推荐实验。

## 2. 什么才算成功

- 推荐比“关键词 + 日期”基线更有用，而不是推荐列表看起来更丰富。
- 覆盖你真正研究的领域；找不到、摘要缺失、来源延迟要可见。每天不必凑足五篇。
- 每条推荐能说明来自哪些兴趣、种子或反馈；词法命中解释不是“论文已证明”的总结，外部黑盒分数也不能伪造解释。
- 画像是你能检查和纠正的数据，不是模型不可见地写出的一段“用户性格”。
- 画像关键词与时间线必须能追溯到本地论文和明确操作记录；没有活动时保持空状态，不把沉默解释成不喜欢。
- 不操作、没时间、以后再看、看不懂都不等于不喜欢。收藏也不自动等于强正样本。
- 关闭电脑或暂停几天，不补发积压“阅读债务”。已有推荐与反馈离线可查看、导出和恢复。
- 推荐和维护画像的质量要分别评估；相关性分数、测试覆盖率、点击量不能替代你的判断。

数值门槛与实验协议见 [ROADMAP](ROADMAP.md) 和 `harness/evaluations.json`，均为待确认目标，不是已通过的指标。

## 3. 最小用户画像

初始只保存可解释结构，算法权重由对照实验决定，不预先绑定 Rocchio、SVM、embedding 或某一框架：

| 内容 | 来自哪里 | 怎样更新 |
|---|---|---|
| 项目 / 研究问题、人工关注和排除主题 | 你明确填写 | 你编辑，版本化保存 |
| 正向种子和明确反例 | 你确认的论文及原因 | 显式添加 / 撤销；未标注候选独立保存 |
| 长期偏好 | 人工固定项、被确认的稳定反馈 | 不因短期没使用而衰减 |
| 当前探索方向 | 近期明确反馈 | 有上限、可冻结；衰减策略先做实验 |
| 熟悉程度 / 时间状态 | “已了解”“看不懂”“没空” | 与兴趣分开，不作为不相关标签 |
| 反馈事件和画像版本 | 每次操作的原始记录 | 记录项目、论文版本、原因、时间、撤销关系；可重放 |

先支持一个研究项目，但存储必须带 project_id，测试跨项目隔离。不在首轮建设泛用知识图谱或跨用户协同过滤；单个用户没有足够行为数据支撑这些额外复杂度。

## 4. 复用优先级

1. **现成系统直接能用，先试用，不另写一个。**
2. 现成系统只缺少反馈语义或本地状态，优先小范围适配 / 上游贡献。
3. 只有端到端系统不适配时，才组合现成抓取、稀疏检索、推荐和导出库。
4. 只有协议/领域需求确有缺口，才自建薄适配层，并留下“不直接复用”的证据。

选型要比较实际代码、许可、隐私和运行开销，不能只看 README 或星数。既有 Electron、TypeScript、SQLite schema、tokenizer、PDF 代码都不是新架构必须保留的前提。

## 5. 范围与暂不做

**核心首轮**：领域与种子、数据源验证、基线推荐、显式反馈、画像检查与撤销、重复控制、最低限度结果展示与原文链接、恢复及本地导出。

**首版已包含（2026-09-11 用户确认，见 [DOMAIN](DOMAIN.md)）**：推荐与画像核心、**推荐论文的 PDF 本地下载与归档（离线可打开）**、**AI 每日速览 + 看不懂时追问**（默认开启，受唯一预算网关与授权约束）。

**后置（独立验收，不阻断推荐核心）**：收藏理由、笔记、高亮锚点、划词翻译/解释、AI 周报润色。顺序由 `READ-01/02`、`AI-03` 的 gate 决定。

**可选接口（不做也不影响核心）**：Zotero/JabRef 只读导入或链接、内嵌 PDF 预览。用户用 Zotero，首版只评估只读/导入，不写入宿主库；确需内嵌时优先复用成熟组件并单独验收许可、选区/锚点与恢复。

**仍不默认引入**：托管后端、云同步、遥测、本地大模型/embedding权重下载、付费模型、私人全文/笔记外发、无界自动 agent 循环。旧资源/隐私约束作为安全下限保留；若某个候选必须改变它们，先提交取舍给你，不暗中启用。

## 2026-09-15 整理建议调整（GRAPH-01）

- 默认建议较宽主题：标题/摘要/主题的本地词汇特征、较低社区分辨率；具有相同明确元数据主题的多数社区可归并，避免邻居上限把同主题拆成方法小簇。分类不依赖预设 AI 学科列表。
- 中文名称、解释与可核对原文关键词；有限本地词汇表只负责名称，不能翻译任意学科。无可靠名称时显示「相关主题 N（待命名）」，仍可编辑。不把中文字符片段冒充专业名称。
- 中英文都参与词汇比较；不等于跨语言语义对齐。单篇/无词汇证据论文保留待整理，不各建方向，不把所有不确定论文并成一个虚假主题。
- 审核弹窗「应用所选建议」为明确选择的论文追加类别，已有分类或手动保护不再导致跳过；原有归属、类别名称、层级和笔记保留。显示实际新增归属及类别数；重复应用明确提示无需重复添加，不产生额外撤销记录。旧自动整理接口的手动保护规则保留。
- 预算仍为零模型 token，无新增网络/模型/数据迁移；词汇分组、元数据主题和有限中文标签均是启发式。不同学科真实质量与最大规模资源消耗尚未测量。

## 2026-10-01 整理建议改为按画像细分（GRAPH-01，取代上节前两条）

- owner 反馈：旧建议按 OpenAlex 学科主题和宽社区分组，把一个研究方向（如世界模型）拆进机器人、多模态等大类，分得太粗，与画像无关。
- 一级类别来自**当前项目画像的固定关键词**：标题或摘要提到该词的论文至少 2 篇才成类。中文名可经有限词表对应英文（「世界模型」匹配 world model）。若某个关键词的论文 80% 以上都属于更大的关键词，就放到那个关键词下面，成为子类。两个关键词覆盖的论文几乎相同（Jaccard ≥ 0.8）时只建一个类，另一个在弹窗里注明。少于 2 篇的关键词不硬造类别，也会注明。
- 子类来自类内**多篇标题共同出现的短语**，每类最多 6 个（如 World Action Model、Video World Model）。画像兴趣词只用于短语打平，不单独成类。不使用 OpenAlex topic，也不使用预设学科表。
- 没有任何固定关键词覆盖的论文，同样按共同标题短语分组；没有共同短语的论文留在待整理。项目还没有固定关键词时，弹窗提示先在画像页固定。
- 弹窗以缩进和「上级 ›」显示层级，并写明每个类别的依据。应用后子类挂在上级之下：上级若未勾选，就找之前已应用的同一建议；找不到时子类成为一级类别。
- 画像词经 worker 的 stdin 传入，不出现在命令行；全程本地、零模型 token、不联网。
- 工具栏去掉了「刷新」按钮（打开页面和保存冲突时会自动刷新）。「撤销」改为写明要撤销的内容，例如「撤销应用建议」；拖动节点、折叠目录这类布局保存不再占用撤销，撤销时保留当前布局。「重新排列」仍可撤销。
- 匹配不跨越逗号、句号、冒号等分句标点（摘要里 “real world. Model …” 不算 world model）。含中文的关键词只做原文匹配，或经词表精确对应英文；不会退化成其中的英文词（「LLM 推理」不等于 LLM）。一级类别最多 12 个，超出的关键词在弹窗里写明，不会悄悄丢掉。
- 数据迁移：旧库的 `org_events` 新增一个可为空的 `label` 列（只加列，旧事件为空、不会被命名撤销）。加列前先在数据库同目录写一份私有备份。
- 撤销「删除类别」时，被删类别原来的位置和折叠状态一并恢复；之后拖动过的其他节点保持当前位置。
- 实测（本机，2000 篇随机合成标题与摘要）：3 个固定关键词约 2.6 秒，无关键词约 3.2 秒，均为单次运行。未测：其他学科真实语料上的分组质量，以及真实大库的耗时。

## 2026-09-15 类别目录（READ-01）

类别支持多层嵌套、新建子类别、改名、调整上级和删除；左栏是单行文件夹目录树：图标、层级线、展开箭头和论文数；每行右侧「⋯」菜单提供新建子类、改名/移动、删除，右侧显示当前位置。论文的「编辑类别」显示已有归属，可勾选多个子方向或取消勾选。批量编辑保持/添加/移除分别明确。父类别视图汇总所有后代论文，每篇只显示一次。类别是树，论文不是文件：同一论文可同时属于多个分支，原文与笔记仍只有一份。

删除类别的应用内确认面板明确：只解除此类别的直接归属，子类别上移一级，论文/PDF/笔记与其他归属保留；撤销可恢复。旧平级类别作为顶层兼容，移动父级不会改论文归属，禁止循环嵌套。图谱区分类别上下级连线与论文归属，折叠分支不隐藏同时属于其他展开分支的论文。详见 [ADR 0007](decisions/0007-category-tree.md)。本功能零新增模型 token。

## 2026-09-30 画像呈现与证据入口

画像页以“当前判断 → 本地证据 → 最近活动 → 本周变化 → 修正入口”为固定阅读顺序。固定关键词、收藏、有用、不相关、太难分别呈现；收藏不自动解释成强正例，太难不显示为负兴趣。所有数字和词项都可展开到当前项目内的论文或明确事件；没有活动不生成趋势，也不把沉默解释成不喜欢。周报保留兼容 URL，但与画像页复用同一套本地零 token 统计。

## 项目创建与跨项目共享（PROJECT-01）

项目创建先保存本地草稿，再由用户确认形成正式项目。AI 引导最多六轮，只能返回结构化的关键词、检索式和学习路径；候选论文始终由本地公开元数据检索生成，用户勾选后才加入项目。没有密钥、预算或网络不可用时，页面切换为明确的本地模式，仍可解析关键词、检索和完成创建。

创建页有三种方式。**快速创建**：一句话目标，一次 AI 调用整理关键词和检索式，自动检索候选，用户审阅后创建。**AI 引导**：最多六次 AI 回合的对话，右侧草稿随对话变化，用户在页面上的修改会带入下一轮。**手动创建**：关键词加种子论文；种子可以粘贴 DOI / arXiv / 链接、按论文名称检索并点选，或把 PDF 拖进来（浏览器本地读取首页识别论文，原文件保存为该论文的 PDF，只有识别出的编号或标题发往 OpenAlex）。所有等待都显示正在做什么和已等多久；每个 AI 回合标明是否真的由 AI 回答、用了多少 token，没有 AI 时说明原因，并可一键重试；没拿到 AI 回答的回合不占名额。候选论文逐条检索、逐批出现，显示作者、日期、摘要和命中的检索式，始终由用户勾选。详见 [ADR 0010](decisions/0010-project-creation-flow.md)。

规范论文事实由全局论文表保存，`project_papers` 保存项目关系，`project_library` 保存项目收藏。一个论文可以显式加入多个项目，但反馈、曝光、收藏、推荐和画像都按项目查询；删除关系不删除论文、PDF、全文或摘要。论文详情提供加入其他项目入口，加入动作幂等，移除只影响当前项目。

## 画像控制与 AI 总开关（2026-09-30）

每个项目的画像可以冻结。冻结后，新反馈照常记录，但不改变推荐向量；钉死词仍可手动修改。解冻后恢复自动学习。“恢复默认”会取消冻结，并把钉死词恢复为创建项目时的关键词；原先的钉死词写入画像版本，可以找回。同一反馈重复提交不产生新事件。撤销反馈会让画像、统计、证据和周报回到反馈之前的状态；因“有用”自动加入的收藏保留，需在论文库单独取消。“太难”只记为熟悉度，不作为兴趣负例。

设置页提供 AI 总开关。关闭后，所有模型请求（包括 dry-run）都会被网关拒绝；推荐、画像、建项目和论文库照常在本地运行。设置接口不回显 API Key，页面也不再显示无法生效的预算控件。详见 [ADR 0009](decisions/0009-gateway-ledger-profile-control.md)。

共享推荐资格遵循 [ADR 0014](decisions/0014-shared-recommendation-eligibility.md)：摘要或当前有效本地正文，项目语言策略作用于新批次；历史与原始资料保留。正文有界且只用于本地排序与匹配，来源或策略在生成期间变化时本轮停止。

## Route V2 生长提议合同（阶段06）

2026-10-07 方向粒度：潜在方向代表可以复用的学习任务。一篇论文可补充已有节点（含已掌握节点）或加入已有提议，不自动成为新方向。数据集、实验对象、版本、细小方法和应用变化不单独立项；新增须说明独立学习能力和路线缺口。必要前置只表示理解已有节点所需的基础，不能把下游应用倒置为前置。相关节点不等于必需前置；独立能力没有确证依赖时先提无硬边新分支，加入后保留原目标和已有边；用户可通过现有编辑功能调整关联和目标。信息不足保留不确定判断；历史提议不自动合并删除，Map 仍须人工确认扩展。

2026-10-07 回复与存储修正：新增提议只用name命名，direction仅用于加入已有提议的d引用。有界普通文字标签兼容为无结构作用的显示数据，不忽略真正引用。有效判断和提议完整保存，不再因已有12条潜在方向而停止后续论文；页面仍按五条展示、模型每批最多三条上下文，确认仍查完整存储。不确定判断可带经校验的相关节点参考，但不保存为覆盖或归属。坏JSON/重复字段/异常字符/遗漏/无效引用/图结构错误给出具体停止原因，保留本次已保存结果。详见[ADR0028](decisions/0028-growth-reply-validation.md)。


2026-10-07 整队列修正：点“让 AI 判断”处理点击时全部待判断论文，自动串行分批，每批不同论文，只算一次每天最多10次的判断任务。每批仍独立受原网关和每请求上限控制，不重试，不追逐处理中新增的论文。显示本次完成数、总数和当前剩余；预算不足、计费未知、无效回复或冲突时保留已完成判断及未完成论文，不称全部成功。新方向仍需用户预览确认。用户本次“肯定就全部看完”要求授权整队列频率和公开元数据范围；总预算保持。见 [ADR0026](decisions/0026-whole-queue-growth-jobs.md)。


学习图生长来自有效“有用”或主动选择种子，包括路径论文。已读懂与曝光不表示兴趣。显式AI判断完整有界Map，可以提议已有节点下的新任务、必要前置、新分支，或判已覆盖/不确定；近邻不是无效方向。用户先看结构、证据与目标影响，再确认或拒绝；证据数/文字相似度不限制手动编辑。图或相关证据变化使意见过期，不自动调用模型。确认和撤销遵守组织revision、有效反馈事务快照。原提议随撤销可恢复，详情见 [ADR 0018](decisions/0018-route-growth-proposals.md)。显式有界AI判断及整队列范围已获用户授权；日常本地核心和手动编辑可用，真实模型质量另测。

## 2026-10-07 分类标准与完整审阅（FIX-CATEGORY-STANDARDS）

取代2026-10-01任意重复标题短语立类规则。整理分类默认走显式 AI 辅助审阅：冻结当前项目或全部论文库的类别、已有归属和未分类论文，逐批元数据审阅；先展示完整整理方案，再统一应用。合理标签保留，不合理标签可改名、合并或删除；删标签同时重新处理论文归属，论文/PDF/笔记保留，整个方案可以撤销。来源不足记未知，不把未读/太难当不合理。类名的中英文明确同义、缩写及单复数共用身份；相关但不同的概念保持独立，父子与不同路径不因相似而合并。研究方向→明确子方向，方法需有支持的方向父级；用户自定义词仍可编辑。

无 AI/未批准/预算不足/坏或截断回复/各批建议冲突/并发变化时明确说明审阅未完成，分类不动；可另点本地检查，合并精确别名、依据有界明确术语提出归类，未知标题残片不再自动立类。关闭审阅或切项目停止后续批次，已发单次请求可能结算；不存在自动重试或静默模型替代。共享或归档论文还挂在待删类别时拒绝删除，须扩大范围或先手工处理。

周报按完整类别路径的中英文身份归并，去重同一论文的别名归属，保留真实事件次数；明确提示统计归并但不静默修改库。用户于2026-10-07明确回复“批准”新AI操作的范围/8000输入2000输出上限；仅显式审阅触发，默认不后台运行且不自动打开AI总开关，原全局额度不增。详见[ADR0027](decisions/0027-category-standards-review.md)。
