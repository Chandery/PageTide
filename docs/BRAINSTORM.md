# 设计头脑风暴：把「推荐 + 画像」做成主体，阅读与 AI 作为第二层

2026-09-11。本页是**探索记录**，用来解释为什么这样划分。一旦本页与 [PRODUCT](PRODUCT.md)、[ROADMAP](ROADMAP.md)、`harness/*.json` 冲突，以那三者为合同，本页只作历史理由。所有数字目标、语言和平台选择仍是**提案**，不是已完成测量。

## 1. 从你的原始想法提取需求

你最初的描述包含五件事，它们经常被混成一个「论文软件」：

1. 每天推 5 篇我领域的新文章。
2. 我选 1 篇精读，系统记录我的画像，逐步优化方向。
3. 每周给我总结。
4. 能连我的论文软件（Zotero）。
5. 有 AI：给我摘要速览、我看不懂能追问，历史要记录。

后来又补了三条更重要的修正：

- 用便宜模型 API（如 DeepSeek），**做之前先算清每天最低开销（以 token 为单位）**。
- 免服务器、本地保存、低算力（一台 Mac / 较差 laptop）。
- 不要重复造轮子；论文推荐和画像网上已有人做；现有 ABCD 顺序不合理，推翻重来。

结论：**主体是「推荐 + 可解释画像」，阅读/笔记/翻译是同一产品的第二层，文献软件连接是可选接口，AI 是挂在主体上的可选加速层。** 顺序必须按风险排：先证明「推荐有用、画像学得对」，再花力气做阅读体验和 AI 配套。

## 2. 关键设计取舍

### 2.1 为什么推荐与画像必须零模型 token

搜索、去重、排序、画像更新都不需要生成模型：

| 环节 | 做法 | 模型 token |
|---|---|---|
| 候选抓取 | 论文元数据 API（arXiv/OpenAlex/Crossref/S2）+ 本地缓存 | 0 |
| 去重/版本 | DOI/arXiv ID 规范化 + 标题指纹 | 0 |
| 排序 | BM25/TF-IDF + 线性分类器（SVM/Rocchio）+ MMR 多样性 | 0 |
| 画像更新 | 显式反馈 → 确定性加权/质心更新，事件可重放 | 0 |
| 归档/维护 | SQLite 表 + FTS5 + 定时 VACUUM/索引 | 0 |
| 本地周报聚合 | 从反馈/曝光表直接算统计 | 0 |

也就是说：**每天最低的「推荐系统」模型开销是 0 token。** 真正的 token 只花在你要求的智能体验（速览、追问、周报润色、划词翻译）。这与「8GB、低算力、无本地大模型」一致，也避免了 LLM 写画像这种不可解释、不可复现的做法。

### 2.2 为什么不做协同过滤 / 深度向量

- 单用户没有协同数据，user-user CF 无从谈起。
- 本地 embedding 需要下载权重 + 推理，违背低算力边界。
- 关键词 + 稀疏检索 + 线性排序在「一个研究领域」的小语料上通常够用，而且**可解释**（能说清是哪些词/种子导致推荐）。
- 只有实验证明稀疏方法明显漏召回/错排序，且语义缺口真实存在时，才另批评估外部/神经方法。

### 2.3 成熟「搜广推」算法的落点（不预锁，按需组合）

| 阶段 | 候选算法 | 用途 | 复杂度 |
|---|---|---|---|
| 冷启动 | 领域关键词 + 分类 + 时间窗 | 有了种子前的兜底 | 低 |
| 召回 | BM25 / TF-IDF（标题+摘要+作者） | 从候选池取相似 | 低 |
| 排序 | Rocchio 质心 / LinearSVC（正例 vs 背景未标注） | 个性化排序 | 低 |
| 重排 | MMR | 多样性，避免 5 篇同质 | 低 |
| 探索 | ε-贪心 / 固定 1 个探索位 | 避免画像自我固化 | 低 |
| 负反馈 | **显式**「不相关」标签提升权重 | 不用「没选」当负例 | 低 |
| 画像结构 | 结构化 JSON：项目、正向种子、显式反例、钉死词、探索主题、熟悉度、事件日志、版本号 | 可看/可改/可撤销 | 低 |
| 更新 | 事件 → 新版本（幂等、可重放、可回滚） | 对照实验可复现 | 低 |

不默认使用：协同过滤、知识图谱、LLM 生成画像、embedding 向量库。

### 2.4 「一篇都不选」和「连续不看」怎么处理

这是产品语义，不是模型问题：

- 当天没选：记录 `no_selection`，**不更新兴趣**，不补发积压。卡片保留可回看，但不会累积成「阅读债务」。
- 连续 N 天没选：只做**提醒与询问**（没空 / 不相关 / 太难 / 太浅），据此调整提醒频率与探索位，不推断不喜欢。
- 长期暂停：冻结画像自动更新，恢复后只从恢复日重新开始，不补历史。
- 监督/督促：本地提醒有上限、可静音；周报只描述实际发生的事，不制造未完成条数。

### 2.5 预览、追问、周报、翻译的边界

- **速览卡片**：只用标题+摘要+来源+理由，一次最多 5 篇、一次调用，输入有上限。
- **追问 agent**：有界的本地检索片段 + 有限轮历史，**不自动调用工具、不无界循环**；答案标注为 AI 生成，不混进用户笔记。
- **周报**：统计部分永远本地零 token；只有你明确开启时才用一次模型润色。
- **划词翻译/解释**：选区短文本、单次调用；不整篇 OCR 上传。
- 所有 AI 内容必须可见来源与「AI 生成」标记；任何调用都必须经过**唯一预算网关**。

### 2.6 Zotero：可选，不当地基

- 第一版**不依赖** Zotero；种子可手填 DOI/arXiv，推荐直接打开原文网页或已有软件。
- 若你用 Zotero：只评估其本地 API 的**只读** collection 元数据；不直接改它的 SQLite，不扫描全部笔记。
- 若你用 BibTeX/JabRef：走标准 `.bib` 交换。
- 把产品做成「论文整理软件」是可行的第二层（收藏理由、笔记、高亮、翻译），但**它不是推荐核心的前置条件**，否则又会重演「先做阅读器」的错误。

## 3. 候选实现路线

| 路线 | 内容 | 优点 | 风险 |
|---|---|---|---|
| **A. 直接用上游** | 跑 arxiv-sanity-X 的纯推荐子集（或 lite） | 复用标签/排序/界面，最快验证 | X 依赖 Intel 扩展、默认开 embedding/备份；Mac arm64 未验证 |
| **B. 薄自建** | 自己写小核心：元数据 API + SQLite FTS5 + sklearn 线性排序 + 自建画像/界面 | 完全可控、低资源 | 可能重复造已有的轮子 |
| **C. 混合（推荐）** | 先 A 探针；能跑就用上游做核心，只小改反馈语义；不行则组合现成库（feedparser / pyalex / rank_bm25 / scikit-learn）做 B | 先复用、后自建，风险可控 | 需要真实测量才能定论 |

**建议顺序**：`REUSE-01` 先做受限适配探针（限时、限改动），`DATA-01` 同时验证你领域的覆盖。探针通过就采用上游；失败记录具体缺口后再批准最小自建层，不退回「大而全阅读器」。

## 4. 第一版形态（macOS only）

不做技术锁定，但给出候选与判据：

| 层 | 候选 | 倾向 |
|---|---|---|
| 推荐/画像核心 | Python（feedparser / pyalex / rank_bm25 / scikit-learn） | 复用上游优先 |
| 存储 | SQLite + FTS5（BM25）；画像/事件用 SQLite 表 + 可导出 JSON | 低资源、可移植 |
| 界面 | ① 本地 loopback 网页（FastAPI/Flask）② Tauri/SwiftUI 壳 ③ Electron | 先 ①/②；Electron 仅在有明确理由时 |
| PDF/笔记 | 先用系统预览/PDFKit；确需内嵌再复用 PDF.js/Zotero reader | 后置 |
| AI | 唯一预算网关 + 可选操作注册表（见预算表） | 后置但已计费 |

判据：8GB 参考机上峰值 RSS、索引时间、排序延迟必须实测；未测不宣称「轻量」。macOS 是首个且唯一目标，Windows/Linux 不在首版承诺内。

## 5. 每日 / 每周主流程（建议）

```text
每日
 1. 从已批准数据源拉「当日/近 N 日」候选          (0 token)
 2. 规范化 ID、去重、剔除已曝光/已反馈             (0 token)
 3. 稀疏排序 + MMR + 探索位                        (0 token)
 4. 出 ≤5 张卡：标题/摘要/来源/发布日期/推荐理由   (0 token)
 5. (可选) AI 速览 1 次调用                        (已登记预算)
 6. 你反馈：有用 / 不相关 / 以后再看 / 没空 / 看不懂 (0 token)
 7. 更新画像版本（可看/可改/可撤销）               (0 token)

每周
 8. 本地统计本周真实活动 → 周报（可选 1 次 AI 润色）
 9. 不生成未读债务；暂停/没空只影响提醒
```

## 6. 已确认的决定（2026-09-11）

- 领域/语言：英文 AI / world models；界面与解释中文。
- 种子：10 篇正例（见 [DOMAIN](DOMAIN.md)）；无反例，记为未知。
- 首版：推荐+画像核心、**PDF 下载归档**、**AI 每日速览 + 追问**；笔记/高亮/划词后置。
- 平台：仅 macOS、免服务器、本地保存。论文软件：Zotero（只读/导入）。

仍待你确认：AI 日/月 token 与金额上限是否接受提案数值；种子是否允许外发；PDF 存本机文件夹还是 Zotero；可选反例。详见 [PRODUCT](PRODUCT.md) §6。
