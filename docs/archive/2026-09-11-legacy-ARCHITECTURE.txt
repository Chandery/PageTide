# 架构、资源与数据契约

状态：首版候选架构，未经产品原型测量。变更须关联 ADR、预算和评估。

## 1. 模块边界

```text
React + TypeScript renderer (sandbox / contextIsolation)
    ↕ typed, allowlisted IPC / preload
Electron main: 文件授权、窗口、Keychain、任务调度、网络代理
    ├─ SQLite worker: 元数据/笔记/历史/FTS5/任务/usage ledger
    ├─ PDF.js workers: 页面渲染/文本提取/选区定位
    ├─ discovery: 数据源适配、去重、增量同步
    ├─ recommendation: BM25/稀疏向量/相关性反馈/MMR
    ├─ profile: 确定性、可撤销更新
    └─ model gateway: 计数 → 预留 → 调用 → 核账 → 释放/待核账
         └─ 明确配置的外部模型 API
```

没有公共服务、localhost HTTP 后端、Docker、Redis、向量服务或常驻 Python sidecar。Python 只用于当前 repo 的零依赖检查工具；应用业务仍用 TypeScript。后续 SQLite 可选 better-sqlite3 + 独立 worker，依赖/打包兼容由 A 阶段验证，不预先承诺版本。

全库解析不会在每次启动重跑。初次导入小批次执行、可暂停；每次只渲染可见 PDF 页和少量邻页。页面图像缓存有上限，退出论文释放。单个 PDF 解析任务并发 1；后台模型请求默认并发 1；不占用主线程执行排序/大查询。

## 2. 低算力推荐基线

每日候选默认最多 200 篇（过多时缩窄时间窗或分页停止），存标题/摘要/来源。BM25 的 FTS5 分数要正确转换/归一化，不能直接和其他量纲相加。

候选用局部稀疏词向量，长期人工种子 + 衰减的近期正样本构成各兴趣簇；明确负反馈只做有上限的降权，不删除原始偏好。Rocchio 思路在文本稀疏向量上应用，参数配置化。保存反馈事件与画像版本，可重放/撤销。

排序组合词相关性、时间、明确排除项；新论文引用数不作为必要条件。最后对候选前 50 篇用 MMR 选最多 5 篇；一轮选取只比较候选与已选项，规模受限，不做全库 O(N²) 图。最多保留一个相邻主题探索位，由词表/明确种子产生，不用无界 LLM 扩词。

这是低算力可解释基线，不保证跨语言/隐含语义召回。若领域样本达不到推荐质量门槛，先改检索词/数据源，再评估单独计费的云 embedding 或重排；不能悄悄恢复本地模型。

## 3. 数据实体和迁移

- Paper / PaperVersion：规范 ID、DOI/arXiv 别名、来源、首次发表/更新/发现日期分开。
- Attachment：原文件只读、路径、哈希、版本；不假定换 PDF 后批注仍有效。
- TextChunk：paperVersion、page、section、quote、offset；双栏排序失败要可见。
- Annotation：PDF 坐标、页码、选区原文及邻文锚点；不存屏幕像素坐标作为唯一依据。
- Note：user/AI/source 来源分类、关联论文/批注、修改历史与标签。
- RecommendationBatch / Impression / Feedback：本地日期、候选/算法版本、展示顺序、理由、明确反馈。
- ProfileSnapshot：长期/近期/项目簇、反馈来源、可撤销 diff；不用一段 LLM 文本当唯一画像。
- Conversation / Message / Citation：用户可见消息、引用、模型/提示版本；不存 API Key 或供应商隐藏推理。
- Job：幂等键、pending/running/succeeded/failed、重试次数、重启恢复策略。
- UsageReservation / UsageEvent：操作、input/output/cache、预留、实际/未知、价格版本、调用 ID、时间。

SQL migration 前建立可恢复快照，失败回滚；release 前实际测试旧库迁移和备份恢复。备份使用 SQLite backup API/一致性快照，不能在 WAL 活跃时只复制主 DB 文件。备份包含附件 manifest+校验和，不包含 API Key；恢复先校验再替换，原库留恢复点。

## 4. API 与模型边界

仅 model gateway 能调用模型；每个调用对应 `harness/budget.json` 中的 operation。普通元数据 HTTP 与模型请求严格区分，未来架构扫描阻止 renderer 或 feature 直接导入 provider SDK。

最小调用层用明确 DTO、限额和 JSON 校验，不引入自动 agent 循环。基本问答是一次检索后一次生成，检索和保存笔记在本地。需要扩展检索时由用户点击，不自动迭代。JSON 无效最多一次受预算约束的重试；失败保留原摘要/本地模板。

初始模型候选为官方当前 `deepseek-flash`，显式禁用 thinking；模型别名、计费、能力须复核并做真实合同测试。不能把“OpenAI-compatible”当作所有模型的计数、usage、JSON schema、tool 行为完全一致。

问答仅检索当前论文少量片段与有上限的历史，不发送全文和全部聊天。预算不足时裁剪/请用户缩小范围/不调用，不能静默换更贵模型。论文指令、恶意 PDF 链接和模型文本不能授予文件/网络权限。

## 5. 隐私与离线

PDF、笔记、画像、usage 默认本地；调用前展示所发送数据类别。默认速览只含公开标题/摘要和已同意的少量兴趣词；私人笔记不得自动加入周报或问答请求。允许逐次授权发送选区。用户通过自定义 endpoint 增加服务时明确授权域名与数据范围。

Electron renderer 禁止 Node 集成；启用 sandbox/contextIsolation/CSP，白名单 IPC 和 URL 协议；外部链接显式打开，防止路径穿越和任意文件读取。API Key 使用系统安全存储；SQLite 默认未加密，说明 FileVault/设备账号保护边界。

离线可读/写/搜/导出；抓取/云问答可见地不可用。资料正文不可信，回答必须标识原文支持、外部知识或推测，点击引用回到原文。无全文时不得给出全文实验结论。

## 6. 资源目标，不是实测结果

参考设备：8 GB Apple Silicon Mac、SSD；第一版 arm64，Intel 待单独测试。

2026-09-10检查当前开发机为arm64、macOS 26.6.2、24 GiB物理内存（`sysctl -n hw.memsize`=25769803776）。它不是8GB验收机；在此机跑通不能证明低配目标通过。

- 启动可交互 p95 ≤ 3 秒（暖启动，10 次；冷启动另报）。
- 空闲 60 秒稳定后，所有应用进程 RSS 合计目标 ≤ 450 MiB。
- 单篇 30 页文本 PDF、1,000 篇元数据、10,000 条笔记的阅读场景 RSS 目标 ≤ 800 MiB。
- 无任务空闲 CPU 均值目标 < 单核 2%；20 次滚动/选区交互 p95 目标 < 100 ms。
- 本地 200 候选排序 p95 目标 ≤ 250 ms；后台可取消、UI 无长任务冻结。

测量记录硬件/OS、构建、fixture哈希、进程口径、采样方法与原始结果。较强机器通过不等于 8 GB 通过。若 Electron 基线本身无法满足目标，先 profile/缓存裁剪；仍失败则在 A 的 gate 调整技术栈或经用户批准调整目标，不能仅修改数字让测试通过。
