# 调研与采用理由

调研日期 2026-09-10。链接与复查期限见 `harness/sources.json`。研究的是适合本项目的代表性系统，不声称存在经过统一评测的“最好 harness”。没有复制第三方源代码或把公共文章当可安装开源系统。

## 1. 参考哪些 agent / harness 实践

| 来源 | 核实的性质 | 采用 | 不采用 |
|---|---|---|---|
| [AGENTS.md](https://agents.md/) / [Agent Skills](https://agentskills.io/specification) | 开放的说明文件/技能格式，客户端支持方式不同 | 小入口、按需读skill、跨agent项目知识 | 误以为Markdown可以强制权限或保证每个agent自动加载 |
| [OpenAI harness engineering](https://openai.com/index/harness-engineering/) | 内部项目的公开工程文章，不是发布的完整开源harness | repo为知识源、短AGENTS、结构化任务、可执行约束 | 大型观测服务、多agent无限循环、照搬其交付速度 |
| [openai/codex](https://github.com/openai/codex) | 本地agent代码Apache-2.0，非模型开源 | 受影响范围测试、schema生成与同步、snapshot复核 | Rust/Bazel全套工具与其项目专用规则 |
| [obra/superpowers](https://github.com/obra/superpowers) | skills/workflow代码MIT | 先设计、拆任务、验证后声明完成，规格与质量两遍review | 每个typo都多agent/设计文档/大计划 |
| [Aider](https://aider.chat/docs/repomap.html) | 工具代码Apache-2.0；repo map是上下文工具 | 少读上下文、Git diff、普通lint/test退出码反馈 | 把repo map当业务知识库或硬预算系统 |
| [Claude Code examples](https://github.com/anthropics/claude-code/blob/main/plugins/README.md) | 公开示例，根许可为commercial/all-rights-reserved | 参考发现/架构/批准/实现/复核的分工 | 假定MIT/Apache、复制代码，或绑定其hooks作为唯一入口 |

本项目用“需求 → 任务 → 变更 → 检查证据 → 交接”的可追溯链，加可复算的预算注册表。并不需要常驻agent orchestrator、向量知识库或模型审查每次变更。

AGENTS 是canonical，技能为`.agents/skills/*/SKILL.md`。不同客户端不自动识别时手动读取；可选单行导入适配器不能复制一份政策。若后续为Claude/Aider添加适配器，需按当时官方文档测试实际加载，而不是在本阶段声称所有客户端均验证通过。

## 2. DeepSeek 计费与合同

[当前价格页](https://api-docs.deepseek.com/quick_start/pricing/)列出 `deepseek-flash` / DeepSeek-V4.1-Flash。Flash高峰每百万input miss $0.30、hit $0.006、output $1.20；非高峰减半。高峰是UTC工作日01–04及06–10；预算不依赖调度到低峰。模型/价格随时可能变，故保存版本与核查日期。

[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion)默认thinking enabled。首版必须显式禁用，显式max_tokens，不传工具。服务商很大的context/output支持不是本应用应使用的上限。

重要：网页缓存返回旧模型enum和旧stream usage描述；独立直连官方页复核到新`deepseek-flash`，最终带usage的chunk含一个choices元素而非额外空choices usage-only帧。**不能把某次抓取到的缓存内容直接当当前合同**。运行时仍须实测而非仅依赖文档。

usage含prompt、cache hit/miss、completion和reasoning分解；reasoning不重复累加。模型别名会路由变化：当前Pro另有即将调整的公告，但本项目不配置Pro自动兜底，因此不把这个短期切换写入默认预算逻辑。

JSON mode不是任意JSON schema可靠性保证。兼容协议可能忽略max_tool_calls等参数；不依赖供应商的“agent兼容”字段作为费用上限。超时/断流可能仍收费，没有usage必须待核账。

## 3. Token计数是否需要强电脑

[官方deepseek-recipe](https://github.com/deepseek-ai/deepseek-recipe/blob/main/docs/tokenizer.md)提供匹配V4/V4.1的prompt encoding与tokenizer，能不加载神经网络权重进行计数。旧tokenizer ZIP有过时代际模板/长度信息，不据此认定当前APIcontext。固定版本、打包体积和macOS运行内存需在A阶段检验。

离线tokenization不等于真实账单完全一致；模型别名、服务端包装都可能变化。std lib预算工具只做算术/契约检查，没有谎称实现官方BPE或测量调用。字数经验换算尤其不适合公式、乱码和中英混合PDF。

## 4. 论文数据源

[arXiv条款](https://info.arxiv.org/help/api/tou.html)：免费API，legacy API至多每三秒一请求、单连接；有领域覆盖限制，PDF许可独立。

[OpenAlex](https://developers.openalex.org/api-reference/authentication)：免费额度+按次费用，关键词search $0.001，list/filter $0.0001；免费额度与网站等共用。官方页面的semantic search价格表与示例有差异，首版禁用该可选能力，启用前再核实账户合同。未进行有key账户请求。

[Semantic Scholar](https://www.semanticscholar.org/product/api)：图谱、相似论文；初始key 1RPS，未认证总额度是全球共享，不是本app的配额。未找到按次美元价不等于无使用限制；要遵守许可和归因。

首版按用户领域只接一个主要源；别的数据源为后续独立任务。不预装共享私钥。论文API的请求数量和费用单独计算，不冒充LLM tokens。

## 5. 低配可行性的证据边界

[Electron性能指南](https://www.electronjs.org/docs/latest/tutorial/performance)强调测量、多进程内存、避免主线程阻塞与不必要依赖。这支持我们的实施方法，但不能证明本app已经达到800MiB。

[SQLite FTS5](https://www.sqlite.org/fts5.html)有BM25，[Rocchio](https://nlp.stanford.edu/IR-book/html/htmledition/the-rocchio71-algorithm-1.html)提供反馈更新思路，[MMR](https://www.elastic.co/search-labs/blog/maximum-marginal-relevance-diversify-results)提供多样性方法。候选有界、稀疏文本计算不需模型权重；算法存在不是用户领域推荐有效的实证。

参见[可行性审查](FEASIBILITY.md)：架构有条件可行，领域数据、8GB性能、PDF定位与真实模型usage为必须验证项，不以调研替代测试。
