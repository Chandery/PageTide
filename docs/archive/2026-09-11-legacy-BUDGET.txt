# Token 预算、核账与变更契约

基线：`harness/budget.json`；公式生成结果见 [BUDGET.generated.md](BUDGET.generated.md)。2026-09-10 提案，未获用户批准，不是实际账单。

## 1. “最低开销”必须分清

- 严格最低 LLM token：**0**。搜索论文 API、本地排序/反馈/数据库/归档不消耗 LLM token；无新内容、复用本地缓存时也不调用模型。但无 AI 模式不能提供新的 AI 解释/翻译。
- 保留每日五篇 AI 速览的低成本设计：先本地筛选，只对最终五篇做一次批量摘要。参考场景约 4,500 token/天，加每周回顾平均约 571 token/天。这些是目标长度假设，不是 tokenizer 实测值或数学下限。
- 单次设计 envelope：五篇批次 input 4,800 + output 1,400 = 6,200；周报 4,800 + 1,200 = 6,000。每天平均不用于日限额，周报日必须一次预留全部 6,000。
- 完成相同任务的真实最低值还取决于领域、语言、摘要长度和模型质量。未提供领域/样本、未实际调用，不能承诺这些长度一定够用。

本地 CPU、内存、磁盘、电费也不是 token。论文数据源收费不应被换算成虚构的 DeepSeek token。

## 2. 计算口径

`tokens = input + output`；`USD = (miss × input_miss_price + hit × input_hit_price + completion × output_price) / 1,000,000`。

保守测算使用官方当前 Flash 高峰价、所有 input 未命中缓存：input $0.30/M、output $1.20/M。输出和输入不能用同一个价格；reasoning 是 completion 的子集，不能加第二次。模型别名不是不可变版本，价格由外部合同决定，不能静默沿用旧值。

参考列是未测量的长度目标；上限列是拟实施的请求 envelope。参考 30 天按 **30 次日任务 + 5 次周报**，不是拿 30/7 冒充真实日历。未授权操作、手动重生成、失败重试、额外对话和新功能不得算成免费。

说明页与 JSON 是分工关系：数字以 JSON 为准，生成表禁止手改；说明页解释假设。`--check` 检查生成表漂移。

不包含税、汇率、论文 API 单独费用、开发 agent 会话、图片/OCR、云 embedding、超出设定的长对话。用户与开发者应尽可能使用不同 Key/账本；本地账本看不到其他软件对同一 Key 的用量。

## 3. 模型操作与压缩策略

所有提示文件必须登记 operation。输入上限包含 system、提示、输出格式示例、元数据、来源标识、选段、历史及协议开销，不只是论文正文。模型响应使用显式 max_tokens，thinking disabled，普通摘要/问答不传 tools。

每日五篇只传标题/ID/摘要/短兴趣词，不上传 200 篇候选。摘要超限先按纸张/来源边界裁剪并标明覆盖范围；信息不足时不得填造结果。问答保留有上限的问题、历史和引用选段，不能把“会话会增长”当作免费能力。不能为了避免拒绝而自动把长输入拆成无限多次请求。

prompt cache 命中只是潜在优惠，不是零 token；本地命中已完成摘要才是零调用。缓存 key 包含内容哈希、prompt版本、模型标识、语言；更新 prompt 不批量后台重算全库，用户需要时再生成。

默认最多一次额外尝试，包括 JSON 修复。一次重试与一次新请求一样要预留。返回截断/空 JSON 保留失败状态，可用原摘要，不反复请求到“看起来成功”。

## 4. 计数与实测计划

官方有不加载模型权重的 tokenizer/encoder；当前 V4.1 工具与旧 ZIP 模板存在代际差异。应固定匹配模型的 tokenizer + prompt encoder commit/hash/license，不使用 tiktoken 或“中文每字多少 token”伪装精确计费。

当前 stdlib checker **没有 tokenizer，不声称能计算实际文本 token，也未实现 app 网关**。它验证预算算术、场景限额、记录和 usage 样例一致性。UTF-8 字节数/字符经验比例只能做预检查，不是服务端 token 上界。

A-04 先离线运行公开/合成样本计数；获授权后小额执行 A-05 校准：中英文、长标题、符号/公式、截断、缓存、usage、流中断、重试。记录 assembled request 的计数、服务端 usage 和差值。只测试当前选用的 Chat Completions 合同，不把其他协议的兼容假设迁入。

若无法可靠计数/核账，默认阻止自动模型任务；可继续无 AI 功能。明确展示估算与待核账状态，不能宣称硬账单保障。预算基线需在看到卡片质量之后确认；如果目标长度不足，先缩范围/改输出，再提预算变更给用户。

## 5. 运行时预算网关（待实现）

1. operation 已登记；用户已允许外发对应数据并批准价格/预算；价格未过复核期。
2. 本地选择证据、组装最终请求、用固定 tokenizer计数；验证整体 input 和 max_output。
3. SQLite 事务同时检查已结算 + 所有未结算预留，对 background/interactive/day/month 和 USD 逐项准入。
4. 在出站前持久化完整 input 上界 + max_output 的 reservation。多个窗口不得各自拿一份余额。
5. 完成后存 provider request ID、usage/cache/价格版本；幂等结算，释放多余预留。
6. 无 usage 的断流/超时保留待核账预留，不能当作零费用；重启仍存在。收到不一致 usage 时隔离记录并暂停该适配器的自动调用。
7. 实际超过预留时仍记真实用量，告警并停止后续调用；不靠截断账本数字“守住预算”。
8. 80% 提醒；额度不足不发请求，解释原因并可改成原摘要/本地周报。人工提高额度要留批准记录。

日界限按用户固定时区；用量归属、跨日预留、跨月未决请求必须测试，改时区或回拨系统时钟不能清零账本。已发出请求的供应商行为不受本地完全控制，真正账户级上限还需供应商提供限额或独立预付 Key。

DeepSeek 文档在缓存页面和直连版本出现 streaming/schema 差异，已经核对直连版本；适配器必须容忍未知合法字段，并以合同测试验证 usage 末帧，不按“OpenAI 一般这样”写死。

## 6. 非 token 支出

- arXiv：官方 API 免费，遵守串行及速率限制。
- OpenAlex：单独额度账本；例子 10 次关键词搜索 + 20 次 filter = $0.012 毛额度消耗，若尚有免费额度通常无需支付。账户在别处使用的额度也占用同一池；首版不启用语义搜索/付费内容下载。
- Semantic Scholar：未发现官方按次美元价，但有 key、限流和许可要求；不当成无限可用。
- 首发开发：签名/公证账号等分发成本单列，未查询用户账号不填数字。

## 7. 每次变化如何动态维护

prompt/model/retry/频率/输入来源/上下文/tokenizer/schema/新工具任一变化：更新 operation → 重算生成表 → 比较 before/after input/output、月量和 USD → 检查最低档设备 → 执行相关回归 → 记录批准与 evidence。

即使总 token 不变，输入变输出也可能涨价；即使价格不变，开放私人笔记上传也需要安全复审。所有 budget/model/prompt/网关改动是 critical，不能归为“小文案”。超出已批准基线、自动频率增加、thinking/图片/工具循环启用需用户批准。基线变更批准后仍保留旧价格版本以核对历史账。

生产 usage 定期在本地聚合 p50/p95/最大值、未知比例、重试率、每有用卡片成本；默认不上传遥测。每个里程碑审核外部价格/协议，价格页至少每30天复查，过期阻止发布/live eval，离线检查不需要联网。

## 8. 开发 agent 本身的预算

另有每工作单元的软预算，记录在 JSON。累计实现者、reviewer、子代理、重试和重复输入；保留 25% 用于验证与交接，最多两轮修复后重新规划。不要求文档 typo 发起 agent 群。

当前宿主未向本项目提供可核算的开发会话用量，因此本次开发 token **unknown**，不是 0。没有宿主计数/取消接口时，AGENTS.md 不能强制限制编码 agent 账单，必须称软预算。运行时用户预算与开发 agent 预算不混淆。
