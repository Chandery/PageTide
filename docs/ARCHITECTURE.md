# 候选架构：围绕推荐与画像组合，而非从阅读器扩展

2026-09-11。旧架构已被 [ADR 0002](decisions/0002-recommendation-first-reset.md) 替代。本页是待验证的边界，不是已经选定的技术栈或已实现组件。

## 1. 先做组合决策

```text
研究问题 / 人工种子 / 明确反馈
           ↓
本地画像与事件记录 ← 用户检查、编辑、撤销
           ↓
数据源适配 → 有界候选快照 → 上游推荐器 / 固定基线
                                  ↓
                        去重、多样性、推荐依据
                                  ↓
                         最小结果 + 反馈界面
                                  ↓
                       原论文网页 / 已有阅读软件
```

优先级是“直接运行候选系统 → 小改上游 → 组合现成库 → 最后才自建缺口”。数据采集、词向量、SVM、排序和文献管理都已有实现；没有证据不能以“更统一”为由全部重写。

必须自己定义的是本产品的研究问题、反馈语义、可撤销事件与验收协议。实现也优先适配已有代码，只有上游缺失或不适配才新增。

## 2. 核心契约

| 边界 | 输入/输出 | 约束 |
|---|---|---|
| Seed/Profile | 项目、主题、论文ID、标签来源、人工固定项 | 收藏/引用/没操作不自动变强正负样本；原始事实与推导权重分离 |
| CandidateSource | 带版本ID、来源、title/abstract、日期的元数据 | 候选上限、分页停止、限流、许可和缺失值可见；检索词也属于外发数据 |
| Ranker | 固定候选集 + 指定画像版本 → score与可用解释依据 | 版本可重现；未知样本不是“用户不喜欢”；黑盒外部服务单独标识 |
| Exposure/Feedback | batch、位置、论文版本、project、动作、原因、时间 | 事件追加；重复操作幂等；撤销可重放；纯UI状态不误写兴趣 |
| ProfileUpdate | 明确事件 → 可查看diff及下一版本 | 自动更新可冻结；长期人工项不能被短期状态覆盖；无活动no-op |
| Capture/Note | 收藏理由、用户笔记、高亮锚点、可选AI文本 | 用户文本与AI文本分开存储与显示；AI不得覆盖/伪装用户笔记；锚点重开后仍可定位 |
| ModelGateway | 已登记操作 + 有界上下文 → 结果或本地降级 | 先预留in-flight/日/月token与USD再发送；无旁路、无静默换模型；未知usage持续预留；除AI层外不调用 |
| Delivery | 少量推荐、过滤/不足原因、原文链接、反馈入口 | 不依赖全文解析或模型生成；不自动补发历史积压 |
| Recovery/Export | 画像、种子、反馈、曝光、算法版本 | 普通开放格式导出，隔离目录恢复演练；不可只测文件存在 |

存储可用上游现有本地数据库加小表，也可先用版本化JSON/SQLite。是否复用旧schema必须经过迁移/恢复检查；旧文件存在不是复用理由。

## 3. 三类画像方法都需比较，不能先定答案

- **可解释稀疏方法**：TF-IDF + 线性分类/相关性反馈。已有轻量开源实现，候选优先；跨语言、术语不同或种子太少可能失效。
- **现成外部推荐服务**：例如以正/负论文ID查询的 Semantic Scholar。可作候选召回或对照，减少自建，但研究兴趣会外发，且不掌握其训练、更新和覆盖边界。
- **语义向量/模型方法**：不少项目默认下载模型或调用API，不能因“代码开源”就认为计算免费/隐私合规。只有前两类在真实样本上暴露明确缺口，再提交许可、运行开销和外发取舍。

本轮不设定Rocchio权重、衰减天数、探索位比例等未经验证的参数。不使用生成模型编写的自然语言画像作为唯一推荐状态。

## 4. 论文软件不是主架构

- 初始种子可手工 DOI/arXiv URL 或文件导出，推荐直接打开原论文页面，不要求先连接任何软件。
- 若你使用 Zotero，可评估其本地API按选定collection只读获取元数据；不直接写它的SQLite、不扫描全部私人笔记。写入/版本兼容单独验证。
- 已实现的 Zotero 路径是“导出文件夹导入”（ADR 0029）：用户在 Zotero 里导出 collection（含文件，BibTeX/RIS/CSL-JSON），应用只读这个文件夹，元数据取自导出文件；不读 `zotero.sqlite`、不用本地 API、不写回。本地 API 和写回仍属 READ-02。
- 若你用 BibTeX/JabRef，优先 `.bib`/标准格式交换，不fork整套Java桌面软件。
- 内嵌阅读器只有确有需要才评估 PDF.js 官方组件或 Zotero reader，后者的AGPL义务与宿主适配成本须明确。现有阅读器修复已取消，不是新架构的底座。

## 5. 未经本次请求改变的安全边界

本地持久化、低资源、无默认模型下载、无托管后端/云同步/遥测、付费和新数据外发先授权、来源文本不可信、保留原件与来源仍成立。

逐项目刷新会把项目关键词（含用户钉住的画像词）作为公开元数据检索词发给 OpenAlex，不含论文 ID、笔记和画像权重（ADR 0012）。

百度学术（ADR 0039，2026-10-23，owner 逐项批准，默认关闭，需要用户自己的千帆密钥）：含汉字的项目关键词（每个项目每次刷新最多 3 个）、创建项目时勾选中文后的检索词和种子论文的中文标题检索会发给 `qianfan.baidubce.com`，密钥只作为不可重定向的请求头发给该主机；百度结果里的 DOI 另发给 OpenAlex（每次刷新一批，打开这类论文时一次）查开放获取 PDF 和语言。画像、笔记、论文库和私有 ID 不外发。本地每天最多 40 次（计数在 `settings` 表，请求前原子预留），响应缓存 24 小时，从不请求也不保存百度的 AI 摘要。每个来源的密钥是否必须、去哪拿、发送什么都以 `SourceInfo` 为准，用户文档骨架见 [SOURCES](SOURCES.md)；来源接口 `search/verify/pdf_routes` 在 `app/source_adapters.py`，每个来源一个 0600 密钥文件（`app/source_keys.py`）。开放获取事实有两个写入者，由 `sources.merge_oa` 合并，不再整体覆盖。

百度搜索限定百度学术站点（`baidu_web`，ADR 0039 增补，2026-10-23，同一批 owner 批准，默认关闭，与百度学术共用同一把千帆密钥）：数据范围与百度学术完全相同（含汉字的项目关键词每个项目每次刷新最多 3 个、勾选中文后的创建检索式、键入的中文种子标题），改发到 `POST https://qianfan.baidubce.com/v2/ai_search/web_search`，请求里只有这一句查询（最长 72 个单位）、固定的站点限定 `xueshu.baidu.com`、web 结果的 top_k，以及 owner 选了时间范围时的 `search_recency_filter`；密钥同样只作为不可重定向的请求头发给该主机。本地每天最多 40 次（与百度学术合计，同一个计数、请求前原子预留；HTTP 429 默认按暂时性限制处理），响应缓存 24 小时（按请求内容的哈希命名，每条留页面、题名、日期和完整的 `content` 文本（含作者姓名），不留 `markdown_content`），没有 DOI 所以不向 OpenAlex 发任何东西。超过百度每月 1500 次免费额度后的计费未验证（owner 待办）。

导入已有论文库（ADR 0029）会把从 PDF 或导出文件里识别出的 DOI、arXiv 编号和论文题目作为公开元数据查询发给 OpenAlex（DOI 每 50 个一批），页面事先写明；PDF 文件、导出文件、论文库、笔记和画像不外发。“联网补全”关闭时导入本身不联网；只有用户在确认页主动「查找」时输入的文字才会发出。整库的 DOI 列表确实会让 OpenAlex 看到这个人读什么，所以它默认开启但必须可见、可关；额度受 OpenAlex 限制，用完时暂停。远程推荐 API 的 ID 集合规则不变，导入不使用它。本地工具访问公开论文元数据不等于0网络；API即使有免费额度也要单列请求和额度。完整语义画像、私有书库和笔记不能为方便集成自动外发。远程推荐API的论文ID集同样揭示兴趣，必须明确授权。

检查更新（ADR 0041，2026-10-24，owner 选定的方案；设置里“自动检查更新”默认开、可关）：已打包的应用最多每 6 小时向 `api.github.com` 请求一次本仓库的 `releases/latest`（公开 JSON，GET，无请求体、无凭据、无 Cookie；User-Agent 只有 `PaperDigHelper/<版本>`），用户点“更新”后再向 `github.com`（及其重定向到的 `*.githubusercontent.com`）下载安装包与 `.sha256`。不发送任何论文、画像、笔记、路径、设备标识或用量；GitHub 能看到的只有请求者 IP 与上述 User-Agent。开关关闭后不再自动请求（设置页的“检查更新”按钮是用户的显式操作，仍会请求）。源码运行没有 `PDH_APP_VERSION`，视为开发版，从不请求。下载只进数据目录的 `updates/`，SHA-256 不符即删除；之后只有这个校验通过的文件会被启动（Windows 安装程序，或 macOS 用新 `.app` 替换旧的），且发生在应用退出之后。零模型 token。

如果选本地HTTP界面，只绑定loopback，检查Origin/CSRF和请求边界，不把“本机”当成无需安全设计。是否常驻、调度和界面框架在小范围试用前决定，不自动沿用Electron。

## 6. 旧资产如何处理

按用户后续“删掉旧PDF开发、重新开始”的要求，旧 `src/`、Electron/React/PDF.js依赖、数据库迁移、tokenizer、应用测试、校准工具和生成器已删除，不再作为底座或冻结代码保留。未触碰真实论文库、应用数据和 `.local/` 私有资料。新架构不继承旧schema；未来若确需导入历史数据，必须另批迁移范围并验证恢复。

预算注册表现为**未批准的 AI 提案**：provider 已登记以便复算每日最低，但 `approved_by_owner=false`、enforcement 与 tokenizer 校准均未实现，核心路径仍为 0 token。旧配置和校准批准不继承；任何真实 AI 调用仍须先验证网关、离线计数与用户授权。重规划时建立的文档/任务快照只用于解释决策，不是可执行实现。

演示项目与新手指引（2026-10-24；[ADR 0042](decisions/0042-first-run-demo-and-tour.md)）：新安装没有项目。演示项目 `pdh-demo` 不在用户的数据库里：请求头 `X-PDH-Demo: 1`（或 `project_id=pdh-demo`）的请求由 `app/demo.py` 路由到 `<数据目录>/demo-sandbox/<世代>/` 下的一次性 SQLite 沙盒，内容由 `app/demo_fixture.py`（29 篇公开 arXiv 论文的元数据、摘要改写、预写中英速览）经真实代码播种；每次开始指引和每次进程启动都新建，旧的尽力删除。沙盒里网关只转发只读状态（任何模型调用、密钥改动都抛错）、数据源与 PDF 抓取是离线桩，零 token、零联网；白名单之外的动作一律 403 `reason_code: demo_readonly`；设置、更新、指引状态等路由永远读写真实目录。指引状态在 `<数据目录>/onboarding.json`（`seen_version`、`completed_at`），不放 `settings.json`（设置页整份覆盖保存）。前端：`tour.js`/`tour.css` 画聚光与气泡，每页 `PDHTour.boot('<页>')` 只显示本页的步骤，跨页状态在 `sessionStorage['pdh-tour']`；主页 `api()` 只在当前项目为演示时加 `X-PDH-Demo: 1`，演示 id 不写 `localStorage`，演示中隐藏会联网、调模型、读 PDF、改数据的入口（`html.pdh-demo` 类）。

数据生命周期：旧默认项目的一次性清理（2026-10-24，[ADR 0042](decisions/0042-first-run-demo-and-tour.md) 补充）：后端启动打开库后检查一次（`app/server.py: build_server → app/legacy_cleanup.py`），只有“`default_project` 完全没被用过”时才在一个事务里删除它和只属于它的种子/抓取论文，之前写 `<库>.pre-legacy-cleanup.bak`；结果记在 `settings.legacy_default_cleanup`，以后不再跑；不用迁移编号。判定与删除清单见 ADR。没有联网、没有模型调用。
