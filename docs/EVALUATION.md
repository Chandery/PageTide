# 评估协议：大模型辅助标注 + 人工抽检

2026-09-11。本页定义「怎么给论文打有用/不相关标签、怎么算推荐好坏」。owner 选择用大模型辅助判断、减少人工标注。本页把这种做法**诚实化**：它可用，但必须记录为代理，并有抽检。

## 1. 两个 provider，职责分开（ADR 0004）

| 角色 | provider | 用途 | 进不进 App |
|---|---|---|---|
| 运行时 | **DeepSeek 官方**（价格可核验） | 排序重排、速览、追问、周报、划词 | 是 |
| 评估裁判 | **taomu 中转 / `gpt-6-astra`**（价格不可核验） | 只给留出集打标签 | **否** |

裁判用**不同模型**，是为了减少「自己给自己打分」的偏差；但这不等于可以免检。

## 2. 三种标签，分开对待

| 标签 | 来源 | 用途 | 能不能当产品结论 |
|---|---|---|---|
| `llm_label` | `judge_relevance`（taomu，对排序不可见） | 全量预标、对照实验的代理标签 | **不能**单独当结论；标为探索性 |
| `human_spotcheck` | owner 抽检一小部分（先自己标，再看 LLM 判断） | 验证 `llm_label` 质量 | 用于判断代理标签是否可用 |
| `pilot_feedback` | 你真实每日使用时的反馈 | 最终价值判断 | 是 |

## 3. 为什么不能只用大模型

- **代理 ≠ 你的偏好**：产品目标是「对你有没有用」。大模型的「相关」不等于你想读。真正的价值判断只能来自 `PILOT-01` 的真实使用。
- 换模型能**减少**自证循环，但不能消除系统偏差（例如它对某些写作风格的偏好）。所以仍需 `E-LLM-LABEL-VALIDITY` 抽检。

## 4. 一次标注怎么跑

```text
冻结留出集（DATA-01 产出，200 篇左右，跨时间切分）
  → judge_relevance（taomu/gpt-6-astra）：每批 ≤20 篇，输入只有画像词 + 标题/摘要（不含名次/分数）
  → 落库：paper_id, useful, confidence, reason, provider/model, prompt_version, set_hash, usage
  → 抽检：随机取 N 篇，owner 先自己标，再对比 LLM 标签，算一致率
  → 一致率达标 → 用 llm_label 跑 CORE-01/EVAL-01 对照
  → 一致率不达标 → 标签不可用，缩小问题或改用人工
```

## 5. 成本口径（重要）

taomu 探针显示**每次请求被注入约 4,403 个隐藏输入 token**，且**无公开价格**。因此：

- 评估预算**只按 token 记**，不计算 USD：`harness/budget.json` 的 `evaluation` 段。
- 每次调用成本 = 登记上限 + 隐藏前缀。标注 200 篇（20 篇/次 × 10 次）上限约 **149,030 token**（已计入前缀）。
- 这是**实验开销**，不占用运行时日/月额度；要控成本就缩小留出集或每批篇数。
- 隐藏前缀不可审计，故 taomu **绝不进入正式产品**；正式调用一律走 DeepSeek 官方。

## 6. 必须记录

- provider、模型与版本、提示词版本、运行时间、集合哈希。
- 每次调用的**真实 usage**（来自 provider 返回，不用估算顶替）。
- 哪些结论来自代理标签、哪些来自抽检、哪些来自真实使用——**三者不能混写**。
- 标题/摘要视为不可信数据：其中的指令一律不执行，无工具调用、无自动重试循环。
